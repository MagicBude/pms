# Phase 3A 第三批：正式采购/外协订单与版本化单据

状态：部分实现（订单领域核心已完成，页面与版本化 Excel 待实现）

## 1. 目标与范围

本批交付 `PUR-003` 和 `PUR-004` 的首个可用闭环：从已提交请购的当前供应商决策生成草稿订单，
按供应商和币种分组，签发稳定编号，取消错误订单，并生成可重复下载、可追溯版本的 Excel 单据。

模型允许未来跨请购合单；首个页面入口一次处理一张请购。付款、审批、收货、订单变更单、PDF
签章、汇率和非物料服务请购不在本批范围。

## 2. 旧数据结论

证据等级均为“源码/数据结构确认”，分析只读取 Git 忽略区，不提交真实业务值：

- 1,625 行形成 536 个订单号，也形成 536 个“订单号 + 供应商”组；没有订单跨供应商。
- 10 个订单跨项目，18 个订单跨请购号，说明项目或请购号不能成为订单头唯一边界。
- 2 个订单混合采购件与加工件，不能强制只用一个零件属性拆单。
- 55 个订单至少一行保存合计与数量乘单价不一致；新系统必须重新计算并在迁移报告中保留差异。

## 3. 业务流程

1. 使用者在已提交请购详情选择“生成订单”。
2. 系统只取有当前供应商决策且尚未被有效订单占用的明细，按供应商和币种分组生成草稿。
3. 使用者核对草稿后签发；系统事务性分配正式编号并冻结签发证据。
4. 已签发订单可生成 Excel。每次生成新增文档版本，不覆盖旧附件关系。
5. 错误订单填写原因后取消；历史订单和已生成文档保留，请购行恢复可下单。

## 4. 状态、编号和金额

| 项目 | 规则 |
| --- | --- |
| 状态 | `DRAFT → ISSUED → CANCELLED`；草稿也只能取消，签发后不可编辑 |
| 类型 | 全采购件为 `PURCHASE`，全加工件为 `OUTSOURCE`，混合为 `MIXED` |
| 分组 | 同一订单供应商、币种一致；项目和请购号允许在明细级不同 |
| 编号 | 签发时生成 `PO/OS/MX-YYYYMMDD-NNN`，租户、日期、类型分别计数 |
| 金额 | 汇总决策冻结的未税、税额、含税金额；不同币种不合计 |
| 文档版本 | 订单内从 V1 递增；同一版本关联一个不可变附件元数据 |

## 5. 权限与审计

- 管理员和生产/采购申请人员可创建、签发、取消和生成单据。
- 项目负责人可按相关项目查看；混合多个项目时，至少与其中一个项目相关即可查看整张订单，
  页面不得因此暴露供应商银行资料。
- BOM 工程和审计角色首版不查看采购商业单据。
- 所有写动作和下载都由服务端校验 tenant、对象范围和稳定权限码，并记录安全审计。

## 6. 图纸包边界

订单 Excel 首先交付。图纸包必须等物料图纸附件具备“物料 + 版本 + 文件校验值”关系后生成；
包内至少包含清单、订单号、物料编码、图纸版本、原文件名和 SHA-256。没有真实图纸关系时页面
显示“图纸待补充”，不能把 BOM 上传源文件复制后称为图纸包。
