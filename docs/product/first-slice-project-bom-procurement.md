# SLICE-001：项目、BOM、投产与生产请购

状态：已接受

## 1. 结论

`项目 → BOM 导入/发布 → 投产发布 → 生产请购` 已确定为首个端到端业务切片。

它位于旧系统业务上游，能够在不引入价格、付款和税务复杂度的前提下，验证主数据、版本、数量计算、防重复、编号、附件、权限、审计、SQLite 持久化和未来租户边界。

用户已于 2026-08-23 接受 P0 分层和第 11 节 `D-S001` 至 `D-S012` 的全部推荐值。

## 2. 目标

使用者能够建立项目，导入并修正 BOM，发布不可静默覆盖的 BOM 版本，按投产数量形成投产需求，并生成唯一、可追溯且不会重复提交的生产请购单。

最终业务结果不是“生成一个 Excel 文件”，而是数据库中形成可查询、可审计的项目、BOM 版本、投产批次和请购记录。Excel 或 PDF 导出属于后续派生能力。

## 3. 范围

### 3.1 包含

- 默认租户和默认管理员初始化；
- 最小客户、物料、单位和分类资料；
- 项目创建、启用、关闭和取消；
- Excel BOM 文件上传、解析、字段映射、逐行校验和原文件留存；
- BOM 草稿、发布、后续版本和版本差异；
- 从已发布 BOM 创建投产批次；
- 按投产台数计算投产需求数量；
- 从投产需求生成生产请购草稿并提交；
- 请购编号、防重复、取消、查询和审计；
- 租户隔离、权限反向测试、重启后数据持久化。

### 3.2 不包含

- 询价、供应商选择、单价和采购订单；
- 入库、出库、付款、发票和经营报表；
- BOM 在线协同编辑器和复杂图形结构；
- 完整旧历史数据迁移；
- 内网认证、PostgreSQL 和云端部署；
- 审批流设计器和任意自定义字段平台。

## 4. 角色与职责

本切片使用系统管理员、项目负责人、BOM 工程人员、生产/采购申请人员和只读/审计人员五类角色。本机版可以由同一人承担多个角色，但权限模型仍保留职责边界。

角色代码、权限代码、默认授权和对象范围以 [角色与权限矩阵](role-permission-matrix.md) 为唯一基线。

## 5. 主流程

```text
建立客户和项目
      ↓
上传 BOM 原文件
      ↓
解析、字段映射、物料匹配和逐行校验
      ↓
保存 BOM 草稿 ──修正错误──┐
      ↓                    │
发布 BOM 版本 ←────────────┘
      ↓
输入投产台数并创建投产批次
      ↓
计算各 BOM 行的投产需求数量
      ↓
排除不可请购项及已经请购的来源数量
      ↓
生成生产请购草稿
      ↓
检查并提交，取得唯一请购单号
```

## 6. 状态模型

本切片包含项目、BOM 版本、投产批次和生产请购四个状态机。状态、迁移动作、前置条件、副作用和测试不变量以 [核心状态机](state-models.md) 为唯一基线。

稳定状态代码如下：

- 项目：`DRAFT`、`ACTIVE`、`CLOSED`、`CANCELLED`；
- BOM 版本：`DRAFT`、`PUBLISHED`、`SUPERSEDED`、`CANCELLED`；
- 投产批次：`DRAFT`、`RELEASED`、`CANCELLED`；
- 生产请购：`DRAFT`、`SUBMITTED`、`CANCELLED`。

## 7. 核心数据

下表定义业务概念，不是最终数据库表设计。

| 对象 | 最小字段 |
| --- | --- |
| 租户 | 内部 ID、名称、时区、状态 |
| 用户/成员 | 内部 ID、租户、显示名、角色、状态 |

| 项目 | 内部 ID、项目编号、客户、设备机型、开始日期、计划完成日期、负责人、状态 |
| 物料 | 内部 ID、件号/编码、名称、规格/型号、品牌、单位、分类、零件属性、状态 |
| BOM 版本 | 内部 ID、项目、版本号、来源附件、状态、创建/发布信息 |
| BOM 行 | 内部 ID、BOM 版本、层级/部套、物料或待匹配信息、单台数量、备注、行号 |

| 投产需求行 | 内部 ID、投产批次、来源 BOM 行、计算数量、是否可请购、排除原因 |

## 8. 业务规则

### 8.1 BOM 导入与发布

- 项目编号在同一租户内唯一。
- BOM 版本号在同一项目内唯一。
- 导入行保留原文件行号，错误必须能定位回原行。
- 单台数量为空、为零、为负数或无法解析时不能发布；是否存在允许零数量的特殊行待确认。
- 单位缺失不能发布；单位换算不在本切片自动推断。
- 有物料编码时优先按租户内编码匹配；无编码时可以给出候选，但不得静默合并。
- 重复行先报告而不是自动相加；由使用者确认合并、保留或修正。
- 已发布版本不可原地修改；变更必须形成新版本并能查看差异。

### 8.2 投产数量

- 已确认公式：`投产需求数量 = BOM 单台数量 × 投产台数`。
- 投产台数必须为大于零的整数，除非业务确认存在非整数批次。
- 发布投产批次时固化 BOM 版本和计算结果，后续 BOM 新版本不反向改变旧批次。
- 使用明确的 `procurement_required` 属性决定是否进入请购，不硬编码中文分类名称。

### 8.3 防重复请购

- 每条请购行必须引用来源投产需求行。
- 同一来源数量不能因刷新、双击、网络重试或重复提交而重复请购。
- 已确认规则：`剩余可请购数量 = 投产需求数量 - 未取消请购数量`，结果不得小于零。
- P0-B 每个投产需求一次性请购，不支持主动拆分。
- 重复调用创建命令应返回已有结果或明确冲突，不得生成第二份相同请购。
- 提交请购时在一个事务内校验剩余数量、生成编号、保存行和写审计。

### 8.4 请购编号

- 首版保留旧格式 `YYYYMMDD-NNN`，对应 [BR-CFG-001](business-rules.md#br-cfg-001-请购单号)。
- 编号在租户内唯一并由服务端生成，不能依赖共享日期工作簿。
- 并发、事务回滚和重试不得产生重复编号；允许因事务安全产生序号缺口。

## 10. 候选验收案例

### AT-S001 初始化本机环境

**Given** 空数据目录和有效本机配置，**When** 首次启动应用，**Then** 系统创建默认租户与管理员；重复启动不会重复创建。

### AT-S002 创建项目

**Given** 已有客户，**When** 项目负责人填写必填信息并启用项目，**Then** 项目可用于导入 BOM，且创建和启用动作进入审计。

### AT-S003 项目编号唯一

**Given** 同一租户已有项目编号 `DEMO-001`，**When** 再次创建同号项目，**Then** 服务端拒绝并返回可理解的字段错误；另一租户的同号项目不受影响。

### AT-S004 导入有效 BOM

**Given** 一个仅含脱敏示例数据的 BOM 文件，**When** 上传并完成字段映射，**Then** 系统生成草稿、逐行结果和物料匹配结果，并保存原文件摘要及关联。

### AT-S005 阻止错误 BOM 发布

**Given** BOM 含空数量、零数量、负数量、未知单位或无法解析的数据，**When** 请求发布，**Then** 服务端拒绝发布并返回对应原文件行号，不产生投产可用版本。

### AT-S006 重复行不静默合并

**Given** BOM 中存在疑似重复行，**When** 完成解析，**Then** 系统显示重复依据和候选处理方式，未经确认不自动相加。

### AT-S007 发布后不可覆盖

**Given** BOM V1 已发布，**When** 使用者尝试修改其业务内容，**Then** 系统拒绝；使用者只能创建 V2，并可查看 V1 与 V2 的差异。

### AT-S008 创建投产批次

**Given** 已发布 BOM 且投产台数为 3，**When** 发布投产批次，**Then** 每个可投产行按已确认公式计算需求数量，并固化来源版本和计算结果。

### AT-S009 幂等生成请购

**Given** 某投产需求尚未请购，**When** 同一个创建请求因重复点击或重试执行两次，**Then** 只形成一份请购来源关系，不重复增加数量。

### AT-S010 并发提交和编号

**Given** 两个允许提交的请求，**When** 几乎同时提交，**Then** 两张请购单号不同且租户内唯一；每张单的行与编号在同一事务中成功或回滚。

### AT-S011 取消不删除历史

**Given** 已提交但尚未进入采购订单的请购，**When** 有权限者按允许规则取消并填写原因，**Then** 状态变为取消，历史、行和审计仍可查看，剩余可请购数量按确认规则恢复。

### AT-S012 跨租户隔离

**Given** 租户 A 和租户 B 均有项目，**When** A 的用户使用列表、直接 ID、附件地址或修改请求访问 B 的数据，**Then** 均不可读取或修改，并记录必要的安全结果。

### AT-S013 重启后保持一致

**Given** 已保存项目、BOM、投产和请购，**When** 本机服务重启，**Then** 数据、状态、附件关联和审计保持一致。

### AT-S014 与旧系统对照

**Given** 一个脱敏的旧项目/BOM 案例，**When** 分别用旧系统和新系统产生请购候选，**Then** 项目、物料、投产数量和去重结果可以逐项对账；有意差异必须记录规则 ID 和接受原因。

用户已于 2026-08-23 接受以下首版决策。后续如需改变，应记录影响，并同步需求、测试和必要 ADR。

| 决策 ID | 问题 | 首版推荐值 | 原因 |
| --- | --- | --- | --- |
| D-S001 | 首个切片 | 接受本提案为 `SLICE-001` | 位于业务上游，能独立验收且避开财税复杂度 |
| D-S002 | 项目编号 | P0 由使用者录入并保证租户内唯一；保留以后自动编号接口 | 旧编号来源尚未提取清楚，先避免猜测规则 |
| D-S003 | BOM 行身份 | 使用内部 BOM 行 ID；来源行号、层级路径、部套代号和名称均作为属性 | 可稳定引用，又不把易变文本拼成主键 |
| D-S004 | 无件号物料 | 允许在草稿中导入；发布前必须人工确认或新建系统物料 ID | 兼容非标件，同时禁止按名称/规格静默误合并 |
| D-S005 | 投产数量公式 | 默认 `单台数量 × 投产台数`；首版不允许逐行覆盖 | 贴近旧字段含义，保持计算可解释；例外先退回修正 BOM |
| D-S006 | 可请购判断 | 使用明确的 `procurement_required` 业务属性；不在代码中硬编码中文分类名称 | 规则可审计、可配置，也避免名称变化破坏逻辑 |
| D-S007 | 分批请购 | P0-B 不支持拆分；每个投产需求一次性请购，P0-C 再评估拆分 | 先保证防重复和对账简单，避免提前引入复杂履约 |
| D-S008 | 请购审批 | 本机版提交即生效并记录操作者；保留未来审批状态扩展点 | 单用户首版无需伪造审批，多人版再按权限启用 |
| D-S009 | 请购编号 | 保留 `YYYYMMDD-NNN`；租户内唯一，允许因事务回滚出现序号缺口 | 便于与旧系统对照；不为追求连续号牺牲事务安全 |
| D-S010 | BOM 发布权限 | BOM 工程人员和管理员可以发布；项目负责人只读，首版不要求双人确认 | 与职责相符，同时避免在首版引入审批流 |
| D-S011 | 本机管理员 | 首次启动创建管理员并要求设置密码；后续使用基础登录会话 | 即使监听 localhost，也避免同电脑其他使用者直接进入系统，并为内网版打基础 |
| D-S012 | BOM 来源文件 | P0 支持 `.xlsx` 和只读解析的 `.xlsm`；默认上限 25 MiB；保留至项目归档后再按策略清理；永不执行宏 | 覆盖主要旧格式，同时控制安全、存储和解析风险 |
