# 新系统功能目录

状态：持续维护（`SLICE-001` 已接受，其余范围继续评审）

本目录从旧功能中提炼业务能力，并补入多人协作、可审计、多租户和商业化所需的平台能力。优先级含义：P0 为基础或首批候选，P1 为核心扩展，P2 为成熟期能力。

## 8. 建议首个业务切片

P0 的实施分层见 [P0 范围评审](p0-scope-review.md)。

已选择的首个切片 `SLICE-001`：`项目 → BOM 导入/发布 → 投产发布 → 生产请购`。

原因：它位于业务上游，能同时验证项目、物料、BOM、编号、去重、附件、审计和 SQLite 数据模型，又暂时避开支付和税务的高风险细节。

角色、状态、字段和权限见已接受的 [SLICE-001](first-slice-project-bom-procurement.md)；可执行场景见 [SLICE-001 验收案例](slice-001-acceptance-cases.md)。

候选 B：`采购订单 → 分批入库 → 完成状态`。

原因：闭环清晰，旧源码规则较明确，适合验证事务、数量约束和状态机，但依赖上游已有订单数据。

候选 B 保留为 P0-C 的后续采购履约方向，不再与 `SLICE-001` 竞争首个切片位置。

## 9. 当前实现边界

Phase 2 的“本机最小可用版本”只表示首个业务切片形成了可安装、可操作、可备份恢复的闭环，
**不表示旧 PMS 的全部功能已经迁移完成**。

当前已经实现的业务主线是：

- `MDM-001` 客户基础档案，以及 `MDM-003` 所需的单位、分类和物料基础资料；
- `PRJ-001` 项目基础档案与启用、关闭、取消状态；
- `BOM-001`、`BOM-002` 安全导入、逐行校验、人工确认、版本发布和替代；
- `PRD-001` 从发布 BOM 按投产台数形成不可变需求快照；
- `PUR-001` 从投产需求生成、提交和取消生产请购，并处理编号、幂等、剩余数量和并发；
- `PUR-002` 对已提交请购录入和比较供应商报价、核算税价金额、撤销报价并追加式确定供应商；
- 采购侧 `MDM-005` 保存报价来源、币种、税率、有效期和冻结价格快照；
- 支撑上述流程的登录、角色权限、tenant 隔离、审计、附件、本机备份恢复和浏览器页面。

容易混淆但**尚未实现**的旧系统能力包括：

- `PUR-003`、`PUR-004` 正式采购/外协订单生成、打印、Excel/PDF 和图纸包；
- `PRD-002` 详细生产安排、责任人、计划日期、进度和完成跟踪；
- `SAL-001` 整机成本、客户报价和销售侧价格核算；采购侧价格核算已实现；
- `SAL-002` 至 `SAL-004` 销售订单、订单变更和开票申请；
- `INV-001` 至 `INV-004` 入库、出库、库存流水和送货单；
- `FIN-001` 至 `FIN-007` 付款、报销、发票、银行和汇票；
- 统一搜索、成本利润、提醒和各类台账报表。

因此目前页面中的“生产请购”是采购需求，不是已经带供应商、价格和金额的正式采购订单；当前
“投产”也不是旧 `生产安排.xlsm` 的完整排产与订单生成能力。后续应按本目录和
[旧系统迁移追踪矩阵](../migration/legacy-to-new-traceability.md)逐个切片设计、实现和验收。
