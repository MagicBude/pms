# 业务术语表

状态：已接受（SLICE-001 范围）

## 1. 目的

本术语表是产品文档、界面、代码、数据库和测试的统一语言。`SLICE-001` 中的同义词必须收敛到本表术语；旧系统原字段可以作为迁移别名保留，但不能继续扩大歧义。

## 2. 组织与身份

| 中文术语 | 代码术语 | 定义 | 边界 |
| --- | --- | --- | --- |
| 租户 | `tenant` | 一家独立使用 PMS 的企业数据与权限边界 | 本机版也有默认租户；租户不是部门 |
| 用户 | `user` | 可以登录系统的自然人身份 | 用户本身不直接拥有租户业务权限 |
| 成员 | `membership` | 用户加入某租户后的身份、角色和状态 | 同一用户未来可以属于多个租户 |
| 角色 | `role` | 一组常用权限的命名集合 | 角色不是业务责任人，也不能替代服务端权限检查 |
| 权限 | `permission` | 对指定业务资源执行某动作的许可 | 默认拒绝；权限代码见 [角色权限矩阵](role-permission-matrix.md) |

## 3. 主数据与项目

| 中文术语 | 代码术语 | 定义 | 边界 |
| --- | --- | --- | --- |
| 客户 | `customer` | 委托项目、购买产品或接收服务的组织 | 不能用联系人姓名代替客户；供应商是另一类主数据 |
| 项目 | `project` | 以项目编号组织客户需求、BOM、投产和后续履约的业务对象 | 项目不是销售订单，也不是文件夹 |
| 项目编号 | `project_number` | 租户内识别项目的业务编号 | 与数据库内部 ID 分离；P0 由使用者录入 |
| 设备机型 | `equipment_model` | 项目所涉及设备或产品的型号描述 | 首版作为项目属性，不作为项目主键 |
| 物料 | `material` | 可以出现在 BOM、投产、请购和库存中的标准化对象 | 可包含非标件；无旧件号时仍需系统内部 ID |
| 物料编码 | `material_code` | 租户内可读的物料业务编码 | 可以为空，但存在时必须按已确认规则唯一 |
| 单位 | `unit` | 数量的计量单位，例如件、套、米 | 首版不自动推断单位换算 |
| 物料分类 | `material_category` | 用于组织物料和辅助业务判断的分类 | 不在代码中硬编码中文分类名 |
| 零件属性 | `part_attribute` | 描述物料制造或采购性质的业务属性 | 与物料分类分开；是否可请购由明确属性决定 |

## 4. BOM 与投产

| 中文术语 | 代码术语 | 定义 | 边界 |
| --- | --- | --- | --- |
| BOM | `bill_of_materials` / `bom` | 描述项目所需部套、物料及单台数量的结构化清单 | BOM 不是上传的 Excel 文件本身 |
| BOM 版本 | `bom_version` | 某项目在特定时点发布的一套 BOM 内容 | 发布后不可原地修改；变更产生新版本 |
| BOM 行 | `bom_item` | BOM 版本中的一个可定位条目 | 由内部 ID 稳定引用；来源行号和层级路径只是属性 |
| 来源行号 | `source_row_number` | BOM 行在上传文件中的原始行号 | 用于错误定位，不能作为永久身份 |
| 层级路径 | `hierarchy_path` | BOM 行在部套结构中的位置表达 | 用于展示和比较，不与物料 ID 混为一体 |
| 单台数量 | `quantity_per_unit` | 制造一台设备所需的某 BOM 行数量 | 必须带单位；发布时要求大于零 |
| 投产批次 | `production_release` | 选择一个已发布 BOM 版本并指定投产台数后形成的业务批次 | 发布后固化来源与计算结果，不随新 BOM 反向变化 |
| 投产台数 | `production_units` | 本次投产涉及的设备台数 | P0 必须为大于零的整数 |
| 投产需求 | `production_requirement` | 某投产批次对一条 BOM 行计算出的总需求 | P0 默认等于单台数量乘投产台数 |
| 可请购属性 | `procurement_required` | 明确表示某物料或需求是否应进入生产请购 | 不根据中文名称临时猜测 |

## 5. 生产请购

| 中文术语 | 代码术语 | 定义 | 边界 |
| --- | --- | --- | --- |
| 生产请购 | `purchase_request` | 从投产需求发起、请求后续采购或外协处理的正式业务单据 | 请购不是采购订单，也不包含供应商和成交价 |
| 请购行 | `purchase_request_item` | 请购单中引用某投产需求的数量记录 | 必须能回溯到投产批次、BOM 版本和 BOM 行 |
| 请购单号 | `request_number` | 请购提交时由服务端生成的租户内唯一业务编号 | 与内部 ID 分离；P0 格式为 `YYYYMMDD-NNN` |
| 剩余可请购数量 | `remaining_requestable_quantity` | 投产需求数量减去未取消请购数量后的结果 | 不能小于零；P0 不支持主动拆分请购 |
| 提交 | `submit` | 将请购草稿转为正式单据并分配请购单号的动作 | 本机版提交即生效，但必须经过服务端校验和审计 |
| 取消 | `cancel` | 保留历史的前提下终止业务对象继续生效 | 取消不是删除，必须记录操作者、时间和原因 |

## 6. 文件、审计与技术性业务概念

| 中文术语 | 代码术语 | 定义 | 边界 |
| --- | --- | --- | --- |
| 来源附件 | `source_attachment` | 触发导入或作为业务证据保存的原始文件 | 文件名不是业务状态，也不是唯一标识 |
| 存储键 | `storage_key` | 存储适配器用于定位二进制内容的内部键 | 不向用户暴露真实服务器路径 |
| 内容摘要 | `checksum` | 用 SHA-256 等算法计算的内容指纹 | 用于完整性和重复检测，不替代权限控制 |
| 业务快照 | `business_snapshot` | 单据形成时保存的必要名称、规格、单位等历史值 | 主数据后续变化不得改写历史单据含义 |
| 审计记录 | `audit_log` | 对关键动作、对象、操作者、结果和时间的不可静默修改记录 | 审计不保存密码、令牌或附件原文 |
| 幂等 | `idempotency` | 同一业务请求重复执行不会产生额外业务结果 | 不等于忽略错误；冲突必须返回明确结果 |
| 内部 ID | `id` | 系统稳定引用记录的非业务主键 | 用户可读编号与内部 ID 分离 |

## 7. 旧字段迁移别名

| 旧字段或称呼 | 统一术语 | 说明 |
| --- | --- | --- |
| 件号/编码 | 物料编码 | 原值可保留，导入后映射到物料内部 ID |
| 投产清单 | 投产批次及投产需求 | 旧文件同时表达批次和明细，新系统拆分 |
| Database 请购数据库 | 生产请购与请购行 | 不再以工作簿充当数据库 |
| 请购日期 | 创建时间或提交时间 | 两者含义不同，迁移时不能混为一个字段 |
| 文件备份 | 来源附件或导出版本 | 根据用途分别进入附件或导出记录 |

## 8. 维护规则

- 新术语进入界面或代码前先更新本表。
- 同一个概念只能有一个首选中文术语和一个首选代码术语。
- 旧系统名称只作为迁移别名，不反向污染新领域模型。
- 新增财务、库存等模块时扩展本表，不重写已经发生的历史含义。
