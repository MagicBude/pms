# SLICE-001 验收案例

状态：已接受

## 1. 目的

本文是 `SLICE-001：项目 → BOM → 投产 → 生产请购` 的唯一正式验收案例基线。它把已经接受的范围、决策、权限和状态机写成可自动化的 Given/When/Then 场景。

实现、测试和人工验收必须引用稳定案例 ID。案例语义发生改变时，应保留 ID 并记录影响；完全不同的业务场景使用新 ID，不能静默改写已经发布的验收含义。

权威输入：

- [SLICE-001 范围与决策](first-slice-project-bom-procurement.md)；
- [业务术语表](glossary.md)；
- [角色与权限矩阵](role-permission-matrix.md)；
- [核心状态机](state-models.md)；
- [业务规则基线](business-rules.md)；
- [附件存储 ADR](../architecture/adr/ADR-0003-attachment-storage.md)。

## 2. 执行约定

### 2.1 关键词

- **Given**：可信前置状态和测试数据；
- **When**：一个主要业务动作；
- **Then**：用户可见结果或核心业务结果；
- **And**：与主要结果不可分割的状态、审计、事务或安全断言。

### 2.2 测试层级

| 标记 | 含义 |
| --- | --- |
| `domain` | 不依赖 Django 或数据库的领域规则测试 |
| `application` | 使用端口替身验证用例编排、权限和失败结果 |
| `sqlite` | 使用真实 SQLite 的 ORM、迁移、约束和事务测试 |
| `postgresql` | 使用真实 PostgreSQL 18 的约束、事务和并发测试 |
| `http` | 使用服务端 HTTP/页面边界验证输入、会话、权限和响应 |
| `storage` | 使用隔离临时目录验证附件存储行为 |
| `manual-assisted` | 需要业务人员、旧系统或人工视觉确认，但应尽量由工具生成对账结果 |

一个案例可以由多层测试共同证明。自动化测试名称或参数化 ID 必须包含对应 `AC-S001-xxx`。

### 2.3 统一断言

除非案例明确排除，所有写操作还必须满足：

- tenant 来自服务端可信成员上下文；
- 无权限、跨租户、状态冲突或校验失败时，核心业务数据不改变；
- 成功状态迁移及其必要副作用在同一数据库事务内完成；
- 错误响应不泄露堆栈、SQL、绝对路径或其他租户对象是否存在；
- 强制审计动作记录租户、操作者、动作、对象、结果和带时区时间；
- 日志与审计不保存密码、令牌、附件原文或完整敏感输入。

## 3. 标准脱敏测试数据

自动化和人工验收默认使用以下虚构数据，不得复制真实客户资料：

| 对象 | 测试值 |
| --- | --- |
| 租户 A | `演示制造一厂`，时区 `Asia/Shanghai` |
| 租户 B | `边界测试企业`，时区 `Asia/Shanghai` |
| 管理员 | `admin_a`、`admin_b`，分别只属于自己的租户 |
| 项目负责人 | `project_manager_a` |
| BOM 工程人员 | `bom_engineer_a` |
| 申请人员 | `requester_a` |
| 审计人员 | `auditor_a` |
| 无对象权限成员 | `restricted_a` |
| 客户 | `演示客户甲` |
| 项目编号 | `DEMO-001` |
| 固定业务时间 | `2026-01-15 09:00:00 Asia/Shanghai` |
| 可请购物料 | `MAT-A001`，单台数量 `2.5 件` |
| 不请购物料 | `MAT-A002`，单台数量 `1 套`，`procurement_required=false` |
| 投产台数 | `3` |

对应有效 BOM 应得到 `MAT-A001` 投产需求 `7.5 件`。测试时钟、UUID 生成器和随机存储键由显式替身控制，不能依赖执行机器当前时间或随机顺序。

Excel 样本必须由测试代码生成或经过脱敏审查。`.xlsm` 安全样本可以包含无害的宏容器标记用于证明“不保留、不执行”，但任何测试命令都不得启动 Excel 或执行 VBA。

## 4. 初始化、身份与持久化

### AC-S001-001 首次初始化默认租户和管理员

关联：`TEN-001`、`IAM-001`、`D-S011`；层级：`sqlite`、`http`

- **Given** 一个空且可写的本机数据目录、有效 `local` 配置和固定时钟；
- **When** 操作者首次执行正式初始化；
- **Then** 系统创建一个默认租户，并引导创建需要密码的默认管理员；
- **And** 管理员通过 membership 属于默认租户，不能绕过登录直接访问业务页面；
- **And** 初始化结果记录应用版本和迁移版本，但不记录密码。

### AC-S001-002 重复初始化保持幂等

关联：`TEN-001`、`IAM-001`；层级：`sqlite`

- **Given** 默认租户、管理员和基础权限已经初始化；
- **When** 以相同配置再次执行初始化；
- **Then** 系统返回已经初始化的明确结果；
- **And** 不创建第二个默认租户、管理员、角色或权限记录；
- **And** 不重置现有管理员密码或成员状态。

### AC-S001-003 登录和停用成员边界

关联：`IAM-001`、角色权限矩阵；层级：`http`、`sqlite`

- **Given** 一个启用成员和一个已经停用的成员；
- **When** 两者分别使用正确密码登录；
- **Then** 启用成员可以建立租户会话，停用成员被拒绝；
- **And** 登录成功、登录失败和退出均写入必要审计；
- **And** 停用成员已有会话不能继续执行受保护业务动作。

### AC-S001-004 服务重启后业务状态保持一致

关联：`PLT-001`、`AUD-001`；层级：`sqlite`、`storage`

- **Given** 已保存项目、BOM、投产、请购、附件关联和审计记录；
- **When** 正常停止并重新启动本机应用；
- **Then** 所有业务对象的 ID、状态、版本和来源引用保持一致；
- **And** 附件摘要与存储对象仍匹配；
- **And** 重启不重复执行初始化或状态迁移。

## 5. 项目

### AC-S001-005 创建项目草稿

关联：`PRJ-001`、`project.create`；层级：`application`、`http`、`sqlite`

- **Given** 项目负责人拥有 `project.create`，且租户内已有有效客户；
- **When** 使用者提交项目编号 `DEMO-001`、客户、设备机型、必填日期和负责人；
- **Then** 系统创建状态为 `DRAFT` 的项目；
- **And** 项目归属当前租户，项目编号与内部 ID 分离；
- **And** 创建动作可审计。

### AC-S001-006 启用满足条件的项目

关联：`PRJ-001`、`project.activate`、项目状态机；层级：`domain`、`application`、`sqlite`

- **Given** 当前租户中一个字段完整的 `DRAFT` 项目；
- **When** 有权限的项目负责人执行 `activate_project`；
- **Then** 项目状态变为 `ACTIVE`；
- **And** 记录 `updated_at`、操作者和状态迁移审计；
- **And** 项目开始允许导入 BOM。

### AC-S001-007 项目编号按租户唯一

关联：`PRJ-001`、`D-S002`；层级：`sqlite`、`postgresql`、`http`

- **Given** 租户 A 已有项目编号 `DEMO-001`；
- **When** 租户 A 再次创建同号项目；
- **Then** 服务端通过业务校验和数据库约束拒绝，并返回项目编号字段错误；
- **And** 租户 B 可以独立创建 `DEMO-001`；
- **And** 两种数据库行为一致。

### AC-S001-008 关闭项目后禁止新增下游记录

关联：`project.close`、项目状态机；层级：`domain`、`application`

- **Given** 一个满足当前关闭条件的 `ACTIVE` 项目；
- **When** 有权限者执行 `close_project`；
- **Then** 项目状态变为 `CLOSED` 并保留历史记录；
- **And** 后续导入 BOM、创建投产或请购的请求均被拒绝；
- **And** P0 不提供把 `CLOSED` 改回 `ACTIVE` 的普通编辑入口。

### AC-S001-009 取消项目遵守下游约束

关联：`project.cancel`、项目状态机；层级：`domain`、`application`、`sqlite`

- **Given** 一个没有已发布 BOM 或不可撤销下游记录的项目；
- **When** 有权限者填写原因并执行 `cancel_project`；
- **Then** 项目状态变为 `CANCELLED`，原因、操作者和时间被保存；
- **And** 项目变为只读但不被物理删除；
- **And** 如果项目已有禁止取消的正式下游记录，同一动作被拒绝且原状态不变。

## 6. BOM 文件、导入和版本

### AC-S001-010 接受规定范围内的 Excel 格式

关联：`BOM-001`、`DOC-001`、`D-S012`；层级：`http`、`storage`

- **Given** 分别准备小于等于 25 MiB 的脱敏 `.xlsx` 和 `.xlsm` 文件；
- **When** BOM 工程人员上传文件；
- **Then** 两种格式均进入隔离上传与校验流程；
- **And** 系统使用内部随机存储键，不把原文件名当作磁盘路径；
- **And** 原文件名、大小、实际类型和 SHA-256 摘要保存为元数据。

### AC-S001-011 拒绝超限或不允许的文件

关联：`DOC-001`、`D-S012`；层级：`http`、`storage`

- **Given** 一个大于 25 MiB 的 Excel、一个伪装成 `.xlsx` 的非 Office 文件和一个不允许扩展名文件；
- **When** 分别上传这些文件；
- **Then** 服务端在解析业务内容前拒绝；
- **And** 不产生 `AVAILABLE` 附件或 BOM 草稿；
- **And** 临时文件被安全清理或进入可对账的失败状态。

### AC-S001-012 永不执行宏、公式或外部对象

关联：`D-S012`、ADR-0003；层级：`application`、`storage`

- **Given** 一个无害的 `.xlsm` 安全样本，包含宏容器标记、公式和外部链接；
- **When** 系统导入该文件；
- **Then** 系统不启动 Excel、不调用 VBA、不执行公式或访问外部链接；
- **And** 不保留 VBA 内容到派生工作簿；
- **And** 必填公式单元格没有可信缓存值时，对应行产生阻断错误。

### AC-S001-013 导入有效 BOM 为草稿

关联：`BOM-001`、`BOM-002`、`D-S003`；层级：`application`、`sqlite`、`storage`

- **Given** 一个 `ACTIVE` 项目和字段完整的有效 BOM；
- **When** BOM 工程人员完成上传与字段映射；
- **Then** 系统原子创建 `DRAFT` BOM 版本和逐行解析结果；
- **And** 每个 BOM 行有内部 ID、来源行号、层级路径、单位和单台数量；
- **And** BOM 版本关联可用来源附件及摘要；
- **And** BOM 版本号在项目内唯一。

### AC-S001-014 无效数量阻止发布并定位原行

关联：`BOM-001`、`BR-BOM-001`；层级：`domain`、`application`、`http`

- **Given** BOM 分别包含空值、零值、负值和无法解析的单台数量；
- **When** 执行校验并请求发布；
- **Then** 每个错误包含来源工作表和来源行号；
- **And** P0 不启用零数量例外，所有上述行都阻止发布；
- **And** BOM 保持 `DRAFT`，不产生投产可用版本。

### AC-S001-015 缺失或未知单位阻止发布

关联：`BOM-001`；层级：`domain`、`application`

- **Given** BOM 行的单位为空或不能匹配当前租户单位；
- **When** 请求发布 BOM；
- **Then** 系统拒绝发布并定位来源行；
- **And** 系统不自动猜测单位或换算关系；
- **And** 其他租户的同名单位不能被跨租户引用。

### AC-S001-016 无件号物料必须人工确认

关联：`MDM-003`、`D-S004`；层级：`application`、`http`

- **Given** BOM 中有名称和规格但没有物料编码的非标件；
- **When** 完成导入；
- **Then** 该行允许保存在草稿中，并显示待确认状态；
- **And** 未人工匹配或新建系统物料 ID 前不能发布；
- **And** 系统不得仅凭名称与规格静默合并物料。

### AC-S001-017 物料匹配受租户边界约束

关联：`MDM-003`、`TEN-001`；层级：`sqlite`、`postgresql`

- **Given** 租户 A 和租户 B 都存在物料编码 `MAT-A001`，但内部 ID 不同；
- **When** 租户 A 导入带该编码的 BOM；
- **Then** 只匹配租户 A 的物料；
- **And** 任何自动候选、错误信息或直接 ID 请求都不泄露租户 B 的物料。

### AC-S001-018 疑似重复行不静默合并

关联：`BOM-001`；层级：`application`、`http`

- **Given** BOM 中存在物料、层级和单位相同的疑似重复行；
- **When** 解析完成；
- **Then** 系统显示重复依据和涉及的来源行；
- **And** 未经显式处理前不自动相加、不删除任一行且不能发布；
- **And** 处理结果记录操作者并保留原始来源证据。

### AC-S001-019 只有规定角色可以发布 BOM

关联：`bom.publish`、`D-S010`；层级：`application`、`http`

- **Given** 一个无阻断错误的 `DRAFT` BOM；
- **When** BOM 工程人员、管理员、项目负责人分别尝试发布；
- **Then** BOM 工程人员和管理员可以发布，项目负责人被拒绝；
- **And** 被拒绝的请求不改变 BOM 或旧版本状态；
- **And** 成功和拒绝结果都按规则审计。

### AC-S001-020 发布版本后不可原地覆盖

关联：`BOM-002`、BOM 状态机；层级：`domain`、`application`、`sqlite`

- **Given** BOM V1 已经处于 `PUBLISHED`；
- **When** 使用者尝试修改 V1 行、来源附件或版本内容；
- **Then** 服务端拒绝原地修改；
- **And** V1 的内容、发布时间和发布人保持不变；
- **And** 普通编辑不能把 V1 改回 `DRAFT`。

### AC-S001-021 发布新版本原子替代旧版本

关联：`BOM-002`、BOM 状态机；层级：`domain`、`sqlite`、`postgresql`

- **Given** 项目已有 `PUBLISHED` 的 V1，且 V2 草稿校验通过；
- **When** 有权限者发布 V2；
- **Then** V2 变为 `PUBLISHED`，V1 在同一事务中变为 `SUPERSEDED`；
- **And** 可以查看 V1 与 V2 的增删改差异；
- **And** 任一保存失败时两个版本均回到动作前状态。

## 7. 投产

### AC-S001-022 只有活动项目和已发布 BOM 可以投产

关联：`PRD-001`、投产状态机；层级：`domain`、`application`

- **Given** 分别准备非 `ACTIVE` 项目、`DRAFT` BOM、`CANCELLED` BOM 和有效的 `ACTIVE` 项目加 `PUBLISHED` BOM；
- **When** 申请人员创建并发布投产批次；
- **Then** 只有有效组合可以变为 `RELEASED`；
- **And** 失败组合不生成正式投产需求。

### AC-S001-023 按固定公式计算投产需求

关联：`PRD-001`、`D-S005`；层级：`domain`、`sqlite`

- **Given** BOM 行单台数量为 `2.5 件`，投产台数为 `3`；
- **When** 发布投产批次；
- **Then** 对应投产需求数量为 `7.5 件`；
- **And** 使用十进制定点计算，不经过二进制浮点；
- **And** P0 不允许逐行覆盖计算结果。

### AC-S001-024 投产台数必须为正整数

关联：`PRD-001`、`D-S005`；层级：`domain`、`http`

- **Given** 投产台数分别为缺失、`0`、负数、`1.5` 和 `3`；
- **When** 请求发布投产批次；
- **Then** 只有 `3` 被接受；
- **And** 其他输入返回字段级错误且不产生正式需求。

### AC-S001-025 明确排除不可请购物料

关联：`D-S006`；层级：`domain`、`application`

- **Given** 同一 BOM 同时包含 `procurement_required=true` 和 `false` 的物料；
- **When** 发布投产批次并生成请购候选；
- **Then** 两类行都形成可追溯投产需求；
- **And** 只有 `true` 的行进入请购候选；
- **And** 排除依据来自明确业务属性，不比较中文分类名称。

### AC-S001-026 已发布投产不受新 BOM 反向影响

关联：`PRD-001`、投产状态机；层级：`domain`、`sqlite`

- **Given** 投产批次 R1 已基于 BOM V1 发布；
- **When** 同一项目发布 BOM V2；
- **Then** R1 仍引用 V1，并保留原投产台数和需求数量；
- **And** 使用 V2 必须创建新的投产批次，不能改写 R1。

### AC-S001-027 取消投产遵守请购引用约束

关联：`production_release.cancel`、投产状态机；层级：`domain`、`application`

- **Given** 一个没有未取消正式请购的 `RELEASED` 投产批次；
- **When** 有权限者填写原因并取消；
- **Then** 状态变为 `CANCELLED`，历史需求仍可查询；
- **And** 如果存在未取消的 `SUBMITTED` 请购，取消请求被拒绝且状态不变。

## 8. 生产请购

### AC-S001-028 一次性生成完整请购草稿

关联：`PUR-001`、`D-S007`；层级：`application`、`sqlite`

- **Given** 一个已发布投产批次含多条尚未请购的可请购需求；
- **When** 申请人员创建生产请购；
- **Then** 系统创建一份 `DRAFT` 请购并引用全部可请购来源；
- **And** 每行申请数量等于该来源的全部剩余可请购数量；
- **And** P0 不提供主动拆分或部分数量输入。

### AC-S001-029 剩余可请购数量不小于零

关联：`PUR-001`、`BR-PUR-001`；层级：`domain`、`sqlite`、`postgresql`

- **Given** 投产需求数量为 `7.5 件`，存在未取消请购数量 `7.5 件`；
- **When** 再次计算请购候选；
- **Then** 剩余可请购数量为 `0 件`，该来源不再生成新请购行；
- **And** 任何可能导致负数的保存被业务规则和数据库防线拒绝。

### AC-S001-030 重复创建请求保持幂等

关联：`PUR-001`、`BR-PUR-001`；层级：`application`、`sqlite`、`postgresql`

- **Given** 同一投产来源尚未请购，并准备一个稳定幂等键；
- **When** 因双击、刷新或网络重试重复执行创建命令；
- **Then** 返回已有草稿或明确幂等结果，不创建第二份来源关系；
- **And** 来源数量只计算一次；
- **And** 不依赖前端禁用按钮保证唯一性。

### AC-S001-031 提交时生成租户内唯一请购号

关联：`CFG-001`、`PUR-001`、`BR-CFG-001`、`D-S008`、`D-S009`；层级：`application`、`sqlite`、`postgresql`

- **Given** 当前租户时区业务日期为 `2026-01-15`，一份有效请购处于 `DRAFT`；
- **When** 申请人员执行提交；
- **Then** 请购状态变为 `SUBMITTED`，取得形如 `20260115-001` 的服务端编号；
- **And** 编号只要求租户内唯一，内部 ID 与请购号分离；
- **And** 本机版提交即生效，不伪造审批人或审批状态。

### AC-S001-032 跨业务日期使用租户时区编号

关联：`CFG-001`、`D-S009`；层级：`domain`、`sqlite`、`postgresql`

- **Given** 服务器 UTC 时间跨越租户 `Asia/Shanghai` 的自然日边界；
- **When** 在边界前后分别提交请购；
- **Then** 编号日期段以租户业务日期为准；
- **And** 新业务日期使用自己的序列范围，不依赖服务器本地时区。

### AC-S001-033 并发提交不重号也不重复请购

关联：`BR-CFG-001`、`BR-PUR-001`；层级：`postgresql`，SQLite 进行串行等价验证

- **Given** 两份合法请购以及两个同时争用同一来源的提交场景；
- **When** 并发执行提交；
- **Then** 独立合法请购取得不同且唯一的编号；
- **And** 同一来源最多一个提交成功，另一个得到明确冲突；
- **And** 任何结果都不会让剩余可请购数量小于零。

### AC-S001-034 提交失败完整回滚

关联：`PUR-001`、请购状态机；层级：`sqlite`、`postgresql`

- **Given** 一份有效草稿，并在编号生成后模拟请购行或审计必要记录保存失败；
- **When** 执行提交；
- **Then** 请购仍为 `DRAFT`，正式编号和行快照没有部分保存；
- **And** 允许出现安全序号缺口，但不能把该编号分配给两张单；
- **And** 系统记录安全的失败结果或 request ID，便于定位而不泄露内部数据。

### AC-S001-035 取消请购保留历史并恢复数量

关联：`purchase_request.cancel`、请购状态机；层级：`domain`、`sqlite`

- **Given** 一份尚无采购订单等不可撤销下游记录的 `SUBMITTED` 请购；
- **When** 有权限的申请人员填写原因并取消；
- **Then** 状态变为 `CANCELLED`，原编号、行快照和提交历史仍可查看；
- **And** 对应数量不再计入“未取消请购数量”，剩余可请购数量恢复；
- **And** 取消不是物理删除，也不能通过普通编辑改回 `DRAFT`。

### AC-S001-036 客户端不能直接指定目标状态

关联：全部状态机；层级：`application`、`http`

- **Given** 任一业务对象及一个篡改了 `status` 字段或目标状态的请求；
- **When** 客户端尝试绕过命名动作直接修改状态；
- **Then** 服务端忽略或拒绝客户端目标状态；
- **And** 只有对应命名用例可以根据当前状态和前置条件决定迁移。

## 9. 权限、租户、附件与审计

### AC-S001-037 默认角色矩阵同时验证允许和拒绝

关联：`IAM-001`、角色权限矩阵；层级：`application`、`http`

- **Given** 五类默认角色及各自授权对象；
- **When** 对每个写权限执行参数化测试；
- **Then** 矩阵标记 `✓` 或有效 `R` 的角色成功；
- **And** 标记 `—` 或超出 `R` 范围的角色被服务端拒绝；
- **And** 业务代码检查权限代码，不比较角色中文名或固定角色代码决定业务结果。

### AC-S001-038 对象范围不能靠猜测 ID 绕过

关联：角色权限矩阵对象范围；层级：`application`、`http`

- **Given** 项目负责人只被授权项目 P1，当前租户另有项目 P2；
- **When** 负责人通过列表、搜索或直接 P2 ID 请求访问 P2；
- **Then** P2 不出现在结果中，直接访问也不返回业务内容；
- **And** 更新、状态迁移和相关审计查询同样被拒绝。

### AC-S001-039 跨租户全入口隔离

关联：`TEN-001`、ADR-0002；层级：`sqlite`、`postgresql`、`http`

- **Given** 租户 A 和租户 B 分别有项目、BOM、投产和请购；
- **When** A 的成员通过列表、直接 ID、修改、状态动作或伪造 tenant ID 访问 B 的对象；
- **Then** 所有入口均不可见、不可修改且不泄露对象是否存在；
- **And** 当前租户管理员也不能跨越租户边界；
- **And** 关键跨租户尝试记录安全审计结果。

### AC-S001-040 附件下载继承业务对象权限

关联：`DOC-001`、`attachment.download`、ADR-0003；层级：`http`、`storage`

- **Given** 一个关联租户 B BOM 的可用附件；
- **When** 租户 A 用户、租户 B 无对象权限用户和租户 B 有对象权限用户分别请求下载；
- **Then** 只有租户 B 有对象权限且具备 `attachment.download` 的用户成功；
- **And** 猜测附件 ID、存储键或原文件名不能绕过应用入口；
- **And** 成功和拒绝下载均按规则审计。

### AC-S001-041 强制审计动作完整且不泄密

关联：`AUD-001`、角色权限矩阵；层级：`application`、`sqlite`

- **Given** 登录、项目状态迁移、BOM 导入/发布、投产发布、请购提交/取消、权限拒绝和附件下载场景；
- **When** 分别产生成功、校验失败、权限拒绝或冲突；
- **Then** 审计记录包含 tenant、actor、action、object、result 和带时区时间；
- **And** 失败记录不会反向制造已成功的业务状态；
- **And** 审计与运行日志均不包含密码、令牌、附件原文或完整文件路径。

### AC-S001-042 备份恢复保持数据库与附件一致

关联：`PLT-001`、`DOC-001`、ADR-0004；层级：`sqlite`、`storage`、`manual-assisted`

- **Given** 一个包含完整 `SLICE-001` 业务链的本机数据目录和已验证备份集；
- **When** 将备份恢复到另一空目录并启动相同应用版本；
- **Then** 项目、BOM、投产、请购、状态和审计记录数量与关键字段一致；
- **And** 附件清单的 ID、大小和摘要全部通过核验；
- **And** 恢复过程不依赖 `.internal/legacy-pms/` 或原机器绝对路径。

### AC-S001-043 使用脱敏旧案例完成结果对账

关联：`PRJ-001`、`BOM-001`、`PRD-001`、`PUR-001`、`BR-PUR-001`；层级：`manual-assisted`

- **Given** 业务人员确认过的脱敏旧项目和 BOM 样本，以及旧系统输出的请购候选基线；
- **When** 新系统按相同项目、BOM 和投产台数生成请购候选；
- **Then** 项目、物料、单台数量、投产数量和去重结果可以逐项对账；
- **And** 每个有意差异记录对应规则 ID、旧结果、新结果、原因和接受人；
- **And** 当前尚未提供该脱敏样本，因此本案例在业务验收前保持“待执行”，不能伪报通过。

### AC-S001-044 创建最小客户资料

关联：`MDM-001`、`customer.manage`；层级：`application`、`http`、`sqlite`

- **Given** 当前租户没有“演示客户甲”，项目负责人具备 `customer.manage`；
- **When** 使用者提交客户名称和首版必填资料；
- **Then** 系统创建归属当前租户、具有稳定内部 ID 的有效客户；
- **And** 创建动作可审计，后续项目通过客户 ID 关联；
- **And** 无权限角色不能创建或修改客户。

### AC-S001-045 创建最小物料及请购属性

关联：`MDM-003`、`material.manage`、`D-S006`；层级：`application`、`http`、`sqlite`、`postgresql`

- **And** 同一租户重复物料编码被拒绝，另一租户可以独立使用相同编码；
- **And** 无权限角色不能创建或修改物料。

## 11. 自动化与人工验收门槛

- 除 `AC-S001-043` 外的案例原则上必须自动化；其中备份恢复可以由脚本驱动并保留人工启动验证步骤。
- `AC-S001-043` 需要业务人员确认脱敏样本和差异，自动化负责导出对账表，人工负责接受业务差异。
- SQLite 是本机端到端验收环境；标记 `postgresql` 的约束和并发案例必须在 PostgreSQL 18 CI 环境同时执行。
- HTTP 验收不能替代领域、事务和数据库约束测试；同一规则可以引用同一个案例 ID 在多层证明。
- 未实现、跳过或仅人工观察的案例必须在交付报告中列明，不能用总通过率掩盖关键失败。
