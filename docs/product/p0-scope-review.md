# P0 范围评审

状态：已接受

## 1. 结论

P0 不应被理解为“第一次全部实现”。当前功能目录中的 P0 同时包含平台基础、业务主数据、项目/BOM、采购订单和入库，若一次完成会形成过大的首版范围。

P0 已于 2026-08-23 确认为三个连续增量：

1. **P0-A 工程与平台最小基础**：让本机版具备正式数据边界、审计和可升级能力。
2. **P0-B 首个业务切片**：完成 `项目 → BOM → 投产 → 生产请购`。
3. **P0-C 采购履约扩展**：再完成 `定价/供应商 → 采购订单 → 分批入库`。

本评审不降低已列功能的重要性，只限定第一次可以独立验收的交付边界。

## 2. P0-A：平台最小基础

| 功能 ID | 首次实现边界 | 暂不包含 |
| --- | --- | --- |
| PLT-001 | localhost、SQLite、本地附件目录、配置分层 | 内网服务、PostgreSQL、云部署 |
| TEN-001 | 初始化默认租户；所有业务记录都带租户归属 | 租户自助注册、套餐和跨租户管理后台 |
| IAM-001 | 初始化默认管理员；基础用户名/密码登录、会话和应用服务权限检查 | 找回密码、单点登录和复杂角色编辑器 |
| AUD-001 | 记录首个切片的创建、发布、提交、取消和失败结果 | 通用审计检索中心和长期归档 |
| CFG-001 | 项目/请购编号配置、租户时区和基础业务字典 | 在线可视化规则编辑器 |
| DOC-001 | 保存 BOM 原文件和项目附件元数据，支持受权下载 | 对象存储、在线预览和全文检索 |

即使本机版只有一个使用者，也保留默认租户、默认管理员和服务端权限检查。这样以后升级到内网版时，不需要重新改造所有业务表和用例。

## 3. P0-B：首个业务切片

建议纳入：

| 功能 ID | 本切片结果 |
| --- | --- |
| MDM-001 | 建立项目所需的最小客户档案 |
| MDM-003 | 建立或匹配 BOM 所需物料、单位和分类 |
| PRJ-001 | 创建、启用、关闭或取消项目 |
| BOM-001 | 导入 BOM，输出逐行错误、警告和匹配结果 |
| BOM-002 | 保存草稿、发布版本、创建后续版本和比较差异 |
| PRD-001 | 按投产台数从已发布 BOM 形成投产需求 |
| PUR-001 | 从投产需求生成不重复、可追溯的生产请购 |

详细方案见已接受的 [首个业务切片](first-slice-project-bom-procurement.md)。

## 4. P0-C：紧随其后的采购履约

以下能力仍是 P0，但不阻塞首个切片验收：

| 功能 ID | 延后原因 |
| --- | --- |
| MDM-002 | 供应商在定价和采购订单阶段才成为必需 |
| PUR-002 | 询价、价格与供应商选择需要额外口径和审批规则 |
| PUR-003 | 采购/外协订单依赖已经提交的生产请购 |
| INV-001 | 入库依赖正式采购订单，适合作为第二个闭环 |

P0-C 完成后，系统将形成 `项目 → BOM → 请购 → 采购订单 → 分批入库` 的完整上游闭环。

## 5. 明确不属于第一次实现

- 报价、销售订单及其变更；
- 付款、报销、发票、银行和汇票；
- 跨模块超级查询和经营分析；
- PostgreSQL、内网多人部署和云端多租户运营；
- 许可证签发、套餐和订阅；
- 对全部旧历史数据的一次性迁移。

这些能力的模型边界要被考虑，但不得提前把代码和界面塞进首个切片。

## 6. 评审标准

只有同时满足以下条件，能力才进入 P0-B：

- 是首个业务结果不可缺少的前置；
- 能用脱敏案例独立验收；
- 不要求先完成财务、税务或复杂审批；
- 能验证未来 SQLite 到 PostgreSQL、单人到多人的关键边界；
- 旧系统有来源证据，或属于平台不可缺少的新能力。

## 7. 确认记录

- 用户于 2026-08-23 接受 P0-A、P0-B、P0-C 分层。
- P0-B 正式编号为 `SLICE-001`。
- 默认管理员、BOM 原文件和其他首版策略采用 [SLICE-001 第 11 节决策](first-slice-project-bom-procurement.md#11-已确认的首版决策)。
