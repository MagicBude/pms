# Phase 3A：供应商主数据基线

状态：已实现第一批（创建、查看、旧数据导入）；更新、合并和停用待后续批次

## 1. 范围

本批实现 `MDM-002` 作为询价、价格确定和采购订单的前置能力：

- 租户级供应商实体、完整组织资料和数据库唯一约束；
- 浏览器供应商列表和新建页面；
- 服务端 `supplier.view` / `supplier.manage` 权限和最小审计；
- 从旧供应商数据库版本化映射并经正式应用用例幂等导入；
- 普通页面、日志和对账报告不展示税号、银行名称、行号或账号。

尚未实现供应商更新、候选重复匹配、合并、停用和变更历史。这些能力不能因为旧 VBA 曾经允许
覆盖记录就直接复制；后续必须定义谁能更新、历史订单如何保持原值，以及合并后引用如何迁移。

## 2. 字段与稳定身份

| 字段 | 用途 | 规则 |
| --- | --- | --- |
| `id` | 数据库和模块关联 | UUIDv7，不对人工承诺固定格式 |
| `tenant_id` | 租户边界 | 所有查询和唯一约束必须包含 tenant |
| `code` | 稳定人工/迁移代码 | ASCII 大写；租户内唯一 |
| `short_name` | 旧系统简称及日常显示 | 允许中文，不承担数据库主键职责 |
| `name` / `normalized_name` | 供应商全称及判重键 | 规范化全称租户内唯一 |
| 联系人、电话、地址、服务、英文资料 | 业务联系和未来单据输出 | 可选；服务端限制长度并统一空白 |
| 税号、开户银行、银行行号、银行账号 | 税务和付款资料 | 敏感；不得进入列表、普通日志或审计摘要 |

旧客户和供应商简称均不符合新系统 ASCII 代码契约。迁移代码使用来源数据集和原始行号稳定生成：
客户 `LEG-C-{来源行号}`，供应商 `LEG-S-{来源行号}`。这是为了跨电脑重复映射得到相同代码；
原简称完整保存于 `short_name`，没有丢失或伪造为英文缩写。

## 3. 重复与冲突规则

- 源码确认：旧供应商入档会检测重复，并允许更新既有记录（`BR-MDM-002`）。
- 本批实测：当前原始包 115 条供应商中，简称和全称分别没有重复。
- 已实现：规范包内代码、简称或全称重复时停止映射；数据库以 tenant + code 和 tenant +
  normalized_name 双重约束阻止并发重复。
- 已实现：重复导入时，稳定代码和所有字段完全一致则复用；任何字段不同则整个批次回滚并报告
  来源行号，禁止静默覆盖。
- 优化建议：后续编辑使用显式“保存修改”，合并使用独立高风险动作；税号和银行账户只作为候选
  匹配依据，不宜在存在空值和历史共用账户时直接定义为唯一键。

## 4. 默认权限

- 系统管理员：查看和维护。
- 项目负责人：租户级查看，用于未来项目询价，不可维护银行资料。
- 生产/采购申请人员：租户级查看和维护，承担供方资料录入职责。
- BOM 工程人员、只读/审计人员：默认无供应商档案权限，避免通过普通只读范围泄露银行资料。

本机默认 admin 拥有全部权限。所有写入仍经过应用服务，页面是否显示按钮不能代替服务端授权。

## 5. 验收边界

- 创建完整供应商后，普通审计摘要只包含供应商代码。
- 同一代码或规范化全称在同一租户不能重复，另一租户可独立使用相同代码。
- 无 `supplier.manage` 权限的成员不能创建供应商。
- 供应商列表不渲染税号、开户银行、银行行号和银行账号。
- 真实映射包首次导入新增 9 个客户和 115 个供应商，第二次导入全部复用且不增加审计记录。
