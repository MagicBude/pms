# 业务规则基线

状态：第一轮提取，待业务评审

## 1. 使用方式

每条规则使用稳定编号。后续需求、领域代码、数据库约束、测试和迁移报告都应引用这些编号。

- **确认**：旧 VBA 或查询中存在直接证据。
- **推断**：行为可以合理推断，但没有完整调用证据。
- **建议**：新系统为了正确性、安全性或可维护性新增的规则。

旧规则不是天然正确。评审后应将结论标为“接受、修订、废弃”，并补充示例和验收测试。

## 2. 编号与主数据

### BR-CFG-001 请购单号

- 等级：确认
- 证据：`生产请购.xlsm / 生成请购单号`
- 旧行为：按自然日维护计数器，格式为 `YYYYMMDD-NNN`；同一批请购行共用单号。
- 新系统要求：由数据库事务原子生成，租户内唯一；并发、失败重试和跨日切换不得重号。格式是否保留待业务确认。

### BR-CFG-002 采购/外协订单号

- 等级：确认
- 证据：`生产安排.xlsm / 生成订单号`
- 旧行为：由承接方名称截取值、日期、当日计数和投产单位截取值拼接。
- 风险：依赖中文字符串固定位置，名称变化会改变编号；并发写日期文件可能重号。
- 新系统建议：保存独立的供应商/组织简称代码，以租户级序列原子生成；展示编号与数据库主键分离。

### BR-MDM-001 客户重复

- 等级：确认
- 证据：`Report Forms/客户入档.xlsm`
- 旧行为：检测重复客户并清空重复输入。
- 新系统建议：显示匹配依据和候选记录，允许取消、查看、受权合并或更新，所有操作留审计。

### BR-MDM-002 供应商重复

- 等级：确认
- 证据：`Report Forms/供应商入档.xlsm`
- 旧行为：检测重复供应商，可更新既有记录。
- 本批决定：稳定供应商代码和规范化全称分别执行租户级唯一约束；旧简称作为独立显示字段，
  规范包内简称重复也会停止迁移。
- 本机证据：当前 115 条供应商原始记录中简称和全称均无重复；税号和银行资料存在空值，银行
  行号/开户行还存在重复，因此只作为后续候选匹配依据，不能直接声明全局唯一。
- 待确认：供应商更新、合并和停用的授权流程，以及候选匹配达到何种条件才允许人工合并。

## 3. BOM、请购与订单

### BR-BOM-001 零数量物料

- 等级：确认存在提醒；处理方式待确认
- 证据：`注册机/无数量提醒.xlsm`
- 旧行为：查找数量为零的物料并提醒。
- 新系统建议：导入时把零数、负数、空值分成明确错误；哪些允许保存、哪些禁止发布由物料类型决定。

### BR-PUR-001 防止重复请购

- 等级：确认
- 证据：`生产请购.xlsm / 数据整理`
- 旧行为：合并投产 BOM 后，与请购数据库映射字段求交集，只保留未请购行；无剩余行时提示没有可提交数据。
- 新系统要求：定义正式的“请购业务键”和可请购剩余数量；命令必须幂等，并由数据库唯一约束或锁保护。

### BR-PUR-002 请购字段

- 等级：确认
- 证据：`生产请购.xlsm` 表头
- 旧字段：项目编号、设备机型、部套代号、部套名称、件号/编码、名称、规格/型号、品牌、单位、单台数量、备注、项目开始时间、计划完成时间、物料分类、零件属性、投产台数、投产单位、接单部门、投产数量、请购单号。
- 新系统建议：拆分项目、BOM 行、投产批次和请购行实体，避免复制可关联的主数据；保留必要快照以重现历史。
- 源码确认：`production_requirements` 的稳定请购边界是“项目编号 + 请购单号”，不能按整个项目
  合并；同一项目可以存在多个旧请购号。
- 源码确认：旧“投产单位”保存的是组织名称而非数量单位；新系统的投产数量单位必须独立确认，
  本批真实待复核样例暂映射为“台”。
- 合理推断：带旧请购号的“加工件”和“采购件”均属于生产需求；零件属性必须保留，供后续采购
  与外协流程分流，而不能在迁移阶段丢弃加工件。

### BR-PUR-003 待下单数量合并

- 等级：确认
- 证据：`生产安排.xlsm / 数据整理`
- 旧行为：按项目和物料相关字段合并请购数量，并扣除已形成订单的数量，得到待安排数量。
- 新系统要求：显式计算 `可下单数量 = 已批准请购数量 - 未取消订单数量`，禁止出现负数；应能下钻到来源行。

### BR-PUR-004 价格与承接方确认

- 等级：确认
- 证据：`生产安排.xlsm / 提交订单`
- 旧行为：提交关注单价、总价、承接方和订单编号；发现未确认价格或承接方时警告，操作者仍可选择继续。
- 待确认：哪些字段应强制阻断，谁有权例外提交，以及例外是否需要理由。

### BR-PUR-005 价格匹配业务键

- 等级：确认
- 证据：`Template/价格确定模板.xlsm`
- 旧行为：以项目编号、件号/编码、名称、规格/型号、品牌、单位、备注七项组合匹配采购项。
- 风险：备注和名称不稳定，可能导致同物多键或误匹配。
- 新系统建议：优先使用物料 ID、BOM 行 ID 或请购行 ID；七字段仅用于旧数据迁移匹配和人工确认。

### BR-PUR-006 正式订单与输出文件

- 等级：确认旧行为；新规则为建议
- 证据：`订单生成.xlsm`
- 旧行为：按订单号和供应商生成订单/送货文件、汇总金额、转换人民币大写并复制图纸；文件存在也被用于识别已打印订单。
- 新系统要求：订单数据库记录是事实来源；PDF、Excel 和图纸包是带版本的派生输出，重打不能改变业务状态。

### BR-SAL-001 订单更改

- 等级：确认存在更正能力
- 证据：`Report Forms/订单更改.xlsm`
- 旧行为：找到原订单后展示并更正。
- 新系统建议：已发布订单只能通过变更单产生新版本；记录差异、原因、申请人、审批人和生效时间，历史版本不可覆盖。

## 4. 库存与履约

### BR-INV-001 应交数量

- 等级：确认
- 证据：`Type-in/Stock-in.xlsm / 提起数据`
- 旧行为：以订单行数量减去累计入库数量，得到本次可交/应交数量。
- 新系统要求：按订单行计算剩余可收数量；取消、退货、超收容差必须另行定义。

### BR-INV-002 禁止超收入库

- 等级：确认
- 证据：`Type-in/Stock-in.xlsm / Worksheet_Change`
- 旧行为：交货数量大于应交数量时提示并阻止。
- 新系统要求：服务端事务再次校验，不能只依赖界面；并发收货后累计数量不得超过订单允许量。

### BR-INV-003 分批入库与订单完成

- 等级：确认
- 证据：`Type-in/Stock-in.xlsm / 提交入库`
- 旧行为：允许多次入库；订单总数量等于累计入库总数量时删除“未完成订单”文件。
- 新系统要求：以订单行履约状态和订单汇总状态表示完成，不删除事实数据或依赖文件存在性。

### BR-INV-004 库存流水

- 等级：建议
- 新系统要求：入库、出库、退货和调整都创建不可静默覆盖的库存事务；余额由事务汇总或受控投影产生。

## 5. 付款与发票

### BR-FIN-001 应付聚合键

- 等级：确认
- 证据：`Report Forms/付款安排.xlsm / 获取数据`
- 旧行为：按项目编号、承接方、订单编号聚合订单金额和付款金额。
- 新系统建议：核销应指向稳定的采购订单/付款对象 ID；项目和供应商作为查询维度，不作为字符串连接键。

### BR-FIN-002 付款提交字段

- 等级：确认
- 证据：`Report Forms/付款安排.xlsm / 提交数据`
- 旧行为：检查付款金额、付款日期、备注和付款凭证的缺失数，用户确认后可以继续；提交时追加时间字符串。
- 待确认：备注是否必填、缺少凭证能否先登记、谁能例外、是否允许超付。
- 新系统建议：使用正式 `created_at`、`created_by`、审批和支付状态，不使用拼接时间字符串充当审计。

### BR-FIN-003 发票可开提醒

- 等级：确认
- 证据：`Report Forms/发票跟踪.xlsm / 数据整理`
- 旧行为：按项目编号、承接方、订单编号汇总订单数量和入库数量；差额为 0 时显示“入库完成，可开发票”，否则显示“入库未完成”。
- 待确认：是否允许部分开票、服务类订单无入库时如何处理、数量与金额哪个是最终口径。

### BR-FIN-004 发票提交字段

- 等级：确认
- 证据：`Report Forms/发票跟踪.xlsm / 提交数据`
- 旧行为：检查发票号、开票日期、付款方；付款方可选公账付款或私账付款；提交时追加时间字符串。
- 新系统建议：发票号唯一范围、发票类型、金额、税率、税额、销方税号、附件和红冲关系应结构化。

### BR-FIN-005 发票台账日期范围

- 等级：确认
- 证据：`Report Forms/发票台账.xlsm`
- 旧行为：按起止日期（含边界）查询；关联进项发票 PDF；公账付款或款未付清时用颜色提醒。
- 新系统要求：日期筛选边界和时区明确；付款状态是结构化值，颜色仅为视图表达。

### BR-FIN-006 多次付款

- 等级：确认
- 证据：`Report Forms/付款台账.xlsm`
- 旧行为：同一对象的多次付款记录会合并展示。
- 新系统要求：保留每笔付款明细，通过核销关系汇总，禁止把多次支付压成不可追溯的一行。

## 6. 报表、附件与授权

### BR-RPT-001 项目利润

- 等级：确认
- 证据：`Report Forms/分析报表.xlsm`
- 旧行为：项目成本为订单总价按项目汇总；输出项目、客户、销售、成本、利润和利润率。
- 待确认：销售和成本含税口径、币种、取消订单、退货、报销、库存结转和期间归属。

### BR-RPT-002 付款期限提示

- 等级：确认
- 证据：`Report Forms/分析报表.xlsm`
- 旧行为：正数显示还有多少天，负数显示已延迟多少天，0 显示今天到期；“发票未开”保持原样。
- 新系统建议：保存到期日和状态，由统一提醒规则计算展示文字，并记录提醒处理结果。

### BR-DOC-001 文件不是业务状态

- 等级：建议，来源于多处旧行为
- 新系统要求：不得以文件是否存在、文件名或目录移动表示“已打印、已完成、已付款、已开票”等核心状态。

### BR-DOC-002 附件身份

- 等级：建议
- 新系统要求：附件使用内部 ID、内容摘要、原始文件名、存储键、版本和业务关联；下载、替换和删除均经过权限与审计。

### BR-LIC-001 授权验证

- 等级：确认旧行为；新规则为建议
- 证据：`ERPList/ERP系统价格查询.xlsm`
- 旧行为：硬盘序列号与 MD5 参与激活验证。
- 新系统要求：私有化使用公钥验证的数字签名许可证；签发私钥和注册机不进入交付应用，云端使用订阅权益。

## 7. 待补规则

- 项目、BOM、请购、订单、收货、付款和发票的完整状态机。
- 每类记录的创建、查看、修改、审批、撤销和导出权限。
- 金额含税/未税、币种、舍入、汇率和红冲规则。
- 超收、退货、退料、退款、预付款、尾款和部分开票规则。
- 附件保留、删除、版本和脱敏策略。
- 报表指标的时间点、数据范围和重算规则。
