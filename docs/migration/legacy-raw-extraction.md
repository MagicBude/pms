# 旧 PMS 核心数据只读提取

状态：第一批核心数据库已完成本机提取

## 1. 用途与边界

本工具把旧 PMS 的核心 `.xlsb` 数据库批量转换为 `pms-legacy-raw-v1` 原始包，供后续字段映射、
正式导入和对账使用。它不启动 Excel、不运行 VBA、不修改旧文件，也不会把原始行直接写入 PMS。

原始包含真实客户、账户、订单、付款、发票和员工信息，只能放在 `.internal/` 或仓库外受控目录，
不能提交 Git、作为测试夹具或通过普通聊天和邮件传输。

## 2. Windows 双击方式

仓库已经安装依赖后，双击根目录的 `PMS-提取旧数据.bat`。脚本会从 BAT 旁边的
`.internal/legacy-pms/` 只读提取，并在 `.internal/migration/` 下创建带时间戳的新目录。每次都建
新目录，不覆盖旧证据。

## 3. 命令行方式

需要自动化或排错时，在仓库根目录执行：

```powershell
uv run python manage.py extract_legacy_data `
  --legacy-root ".internal/legacy-pms" `
  --output ".internal/migration/raw-20260824-core-v1" `
  --include-restricted
```

不写 `--include-restricted` 时，只提取不含账户、财务或员工敏感字段的数据集。输出目录必须尚不
存在；任何源文件缺失、工作表变化、表头漂移或单元格类型异常都会中止，并且不会发布半份目录。

## 4. 输出格式

`manifest.json` 保存 schema version、UTC 提取时间、源相对路径、工作表、精确表头、文件大小、
SHA-256、记录数和对应 JSONL 文件。它不保存本机绝对路径。

每个 JSONL 数据行包含：

- `source_row_number`：旧工作表中的一基行号；
- `cells`：与 manifest 表头等宽的单元格数组；
- 每个非空单元格包含 `type` 和字符串化 `value`，数值不会变成 JSON 浮点数。

表头允许旧数据中真实存在的重复名称，例如付款台账的两个“备注”；使用有序 cells 而不是按表头
建立对象，避免重复列静默覆盖。

## 6. 与换电脑的关系

- **完整换机**：使用 PMS 正式备份与恢复，保证 SQLite 和附件一致；不要只复制原始包。
- **旧系统批量迁移**：使用本工具生成原始包，再经过模块映射和正式导入。
- **人工查看或跨系统交换**：后续使用模块级 Excel/JSON 导出，不能编辑数据库备份。

三个用途共享“版本、摘要、校验、不可覆盖”原则，但格式和恢复语义不同，详见
[ADR-0005](../architecture/adr/ADR-0005-data-portability-and-legacy-extraction.md)。
