# 数据迁移总策略

状态：已接受

## 1. 目标

旧系统是需求和迁移来源，不是新系统运行依赖。迁移采用“只读提取 → 脱敏暂存 → 严格受控包 →
正式应用用例 → 结构化对账 → 人工签收”的流水线，禁止让任意旧工作簿、VBA 或路径直接进入新
PMS 进程。

## 2. 数据区边界

- 原始旧文件只保留在被 Git 忽略的 `.internal/legacy-pms/`，不执行宏，不批量改写。
- 含真实业务信息的导出、清洗中间件、对账报告和附件放在受控外部目录，不提交仓库。
- 仓库测试夹具只能使用完全虚构的名称、编号、数量和附件。
- 迁移输入不得包含密码、令牌、许可证私钥、任意文件路径或未声明扩展字段。

## 3. 每类迁移的固定步骤

1. 明确来源文件、工作表、字段、证据等级和业务责任人。
2. 定义版本化输入 schema、字段映射、空值解释、Decimal/日期格式和租户归属。
3. 只读提取到外部暂存区，保留来源行号和原始值摘要。
4. 业务人员确认脱敏样例及旧系统输出基线。
5. 在停止写入的维护窗口备份当前 PMS，再执行迁移。
6. 迁移适配器只调用正式应用用例，不绕过权限、状态、事务、附件和审计。
7. 输出记录数、关键字段、数量/金额和代表性业务链对账报告。
8. 每个有意差异记录稳定检查键、规则 ID、旧值、新值、原因和接受人。
9. 业务签收后保存输入、报告、应用版本和备份集；失败时从备份恢复，而不是手改数据库。

## 4. 可重复与冲突语义

- 稳定代码、项目编号、BOM 版本和显式幂等键用于识别已完成步骤。
- 再次执行必须复核既有对象的全部受控字段；一致则复用，不一致则停止并报告冲突。
- 不能通过“存在就跳过”掩盖字段差异，也不能为了继续执行自动覆盖正式业务数据。
- 多步迁移在合法阶段中断时允许保留已完成对象；下一次从一致对象继续。
- 迁移只在停止本机服务的维护窗口单进程执行，不以此替代内网并发导入设计。

## 5. 验收等级

| 等级 | 含义 | 是否关闭业务验收 |
| --- | --- | --- |
| `TECHNICAL_ONLY` | 完全虚构样例验证 schema、用例编排、幂等和报告 | 否 |
| `BUSINESS_CONFIRMED` + `MATCHED` | 业务已确认样例且新旧逐项一致 | 是 |
| `BUSINESS_CONFIRMED` + `ACCEPTED_DIFFERENCES` | 每个差异有规则、原因和接受人 | 是 |
| `DIFFERENCES_PENDING` | 存在未签收差异，命令返回失败 | 否 |

`AC-S001-043` 只能由后两种业务确认结果关闭。自动化生成的虚构样例永远不能升级为业务签收。
