# PMS 正式切换清单

状态：持续维护（2026-08-26 基线）

## 1. “可以使用”的三个层级

| 层级 | 含义 | 当前结论 |
| --- | --- | --- |
| 新业务试用 | 在新 PMS 中录入新的项目、BOM、投产、生产请购、询价和采购订单 | **可以**，Phase 2 已签收，Phase 3A 新订单链已实现 |
| 单模块切换 | 某个旧工作簿停止新增，历史数据和新业务都转入新 PMS | **尚未完成**，客户/供应商最接近，仍需更新/合并流程签收 |
| 旧 PMS 整体停用 | 所有仍在用的生产、采购、库存、销售和财务入口均被替代 | **不可以**，Phase 3B–3E 尚未实现 |

“代码能运行”不等于“旧系统可停用”。任何模块只有同时通过功能、迁移、对账、业务签收和回退
演练，才能从旧系统停止新增。

## 2. 单模块切换的五道门槛

1. **功能完成**：正常、重复、撤销/更正、权限和租户边界有自动测试。
2. **真实数据映射**：旧字段进入版本化规范包，未知和冲突不靠猜测填充。
3. **隔离导入对账**：在全新 SQLite 中导入，记录数、金额、状态和来源链自动核对。
4. **业务签收**：使用者确认代表案例、差异和例外处理，签收证据进入文档或报告。
5. **切换与回退**：切换前完整备份，明确旧入口只读时间点，并完成恢复演练。

缺少任一道门槛时，可以继续开发或试用，但不能宣称已经替代旧系统。

## 4. 采购订单最近切换路径

1. 将51个订单项目、1,280个订单物料和对应生产请购映射成全量来源规范包。
2. 解决5个缺少销售客户证据的项目和4个无法关联生产需求的来源键。
3. 在全新隔离库导入来源包，使1,625条订单明细的五类引用预检全部通过。
4. 导入536张历史订单，重复执行不得新增或漂移。
5. 输出55张 Decimal 精确金额差异清单，由使用者逐单复核并签收。
6. 做备份、恢复和旧订单入口只读演练，才允许采购订单模块切换。

## 5. 整体停用旧 PMS 的退出条件

- Phase 3A–3E 中仍实际使用的模块全部完成上述五道门槛。
- 原始数据集、规范包、目标记录和附件都有数量及摘要对账，没有静默丢行。
- 所有待确认差异都有具名签收，未知税务、金额或客户关系未被伪装为已确认事实。
- 使用者完成一段并行运行，确认新旧新增业务不会两边同时录入或遗漏。
- 完整备份、空目录恢复和恢复后启动演练通过。
- 明确旧 PMS 的只读归档位置、访问权限和保留期限。

达到这些条件时，更新本文件、[项目状态](../../PROJECT_STATUS.md)、[路线图](roadmap.md)和
[变更记录](../../CHANGELOG.md)，记录正式切换时间点与回退基线。

最终数据交付统一遵守 [ADR-0010](../architecture/adr/ADR-0010-consolidated-legacy-import-bundle.md)：
默认一个总迁移 ZIP 和一个双击 BAT，不要求使用者逐个运行内部模块命令。
