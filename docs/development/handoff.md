# AI 与跨电脑交接说明

状态：强制执行

目标是让新的开发者或 AI 不依赖聊天记录、个人记忆和特定电脑即可判断“项目做到哪里、为什么这样做、下一步是什么”。

## 开始任务

1. 阅读根目录 `PROJECT_STATUS.md`，确认阶段、下一步和阻塞。
2. 阅读 `AGENTS.md`、项目蓝图和任务相关规范。
3. 阅读路线图与最近两条工作日志。
4. 用 `git status` 检查未提交修改；不得覆盖来源不明的改动。
5. 若任务涉及旧系统，只读检查 `.internal/legacy-pms/`，并标明结论是“源码确认”“合理推断”还是“优化建议”。

## 工作过程中

- 稳定需求写入 `docs/product/`，不能只留在对话中。
- 重大技术选择写 ADR，记录背景、选择、备选方案和后果。
- 每条新功能使用稳定功能编号；业务规则、测试和迁移映射引用同一编号。
- 发现旧行为不一致时保留证据和冲突，不擅自挑一个当真相。
- 临时分析输出放 `.tmp/` 或系统临时目录，不提交真实数据和完整 VBA 导出。

## 结束任务

至少完成以下检查：

1. 更新 `PROJECT_STATUS.md` 的日期、完成项、进行项、下一步和验证结果。
2. 在 `docs/development/work-log.md` 顶部追加本次事实、判断、验证和下一动作。
3. 有用户可见变化时更新 `CHANGELOG.md` 的 `[Unreleased]`。
4. 范围或优先级改变时更新路线图和功能目录。
5. 规则改变时同步业务规则、追踪矩阵、实现注释和测试。
6. 运行与改动相称的格式、链接、静态检查和测试；未配置的检查应如实写明。
7. 最终交接说明列出已完成、未完成、验证、风险和建议下一步。

## 文档职责

| 文档 | 回答的问题 | 更新时机 |
| --- | --- | --- |
| `PROJECT_STATUS.md` | 现在在哪里、下一步是什么 | 每个工作批次 |
| `docs/development/roadmap.md` | 各阶段准备做什么 | 阶段或优先级变化 |
| `docs/development/work-log.md` | 实际做过什么、验证了什么 | 每个工作批次 |
| `CHANGELOG.md` | 仓库对使用者产生了什么变化 | 有可见变更时 |
| `docs/product/feature-catalog.md` | 新系统准备提供什么能力 | 产品范围变化 |
| `docs/product/business-rules.md` | 业务必须如何判断和计算 | 规则发现或变更 |
| `docs/migration/legacy-to-new-traceability.md` | 旧能力迁到哪里、如何验收 | 提取或迁移进展变化 |
| ADR | 为什么作出不可轻易逆转的技术决定 | 决定实施前 |

## 禁止作为交接依据

- 仅存在于某次聊天中的计划；
- 某台电脑的绝对临时路径；
- 未提交的完整旧数据副本；
- 没有证据等级的“旧系统就是这样”的描述；
- 只有勾选项、没有验收结果的完成声明。
