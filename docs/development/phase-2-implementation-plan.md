# Phase 2 本机最小可用版本实施计划

状态：执行中

## 1. 目标与约束

本计划把已接受的 `SLICE-001` 和 `AC-S001-001` 至 `AC-S001-045` 转换为可独立验证、可回滚的
实施批次。实现继续使用同一套模块化单体业务代码；Phase 2 只启用 localhost、SQLite 和本地
附件，不提前引入内网 PostgreSQL 部署或云端多租户运营能力。

既有租户、身份、权限、审计、附件、启动、备份与恢复基础必须复用。所有页面从服务端会话取得
可信 tenant，不接收客户端任意 tenant 标识；所有业务写操作经应用服务完成，页面不能直接决定
状态或跨模块保存模型。

## 3. 代码结构

业务数据仍由既定模块分别拥有：

```text
master_data -> projects -> bom -> production -> procurement
      |            |          |          |             |
      +------------+----------+----------+-------------+
                         presentation
```

- `domain/` 保存状态、值对象、公式和不变量，不导入 Django；
- `application/` 保存命名用例、输入输出 DTO、授权和事务编排；
- `infrastructure/django/` 保存本模块 ORM 映射和查询实现；
- `presentation/` 保存表单、视图和 URL，只调用应用用例；
- 模板提供服务端渲染交互，首版不增加前端构建链。

跨模块外键只表达稳定关联。下游模块不得写上游表；需要的历史信息在发布或提交边界固化为
快照，避免主数据变化反向改写历史结果。

## 4. 验证策略

- 领域单元测试覆盖状态转换、数量公式、无效输入和幂等规则；
- SQLite 集成测试覆盖迁移、唯一约束、事务、编号和重启持久化；
- PostgreSQL CI 覆盖租户约束、并发提交和数据库行为差异；
- 页面测试覆盖登录、CSRF、权限拒绝、对象猜测和完整正常路径；
- 附件测试覆盖类型、大小、公式/宏安全边界、下载授权和原文件摘要；
- 备份恢复测试必须包含完整项目、BOM、投产、请购、附件与审计记录；
- 每条正式验收案例在测试名、测试说明或退出矩阵中保留稳定 ID。

## 5. 旧数据迁移与对账

P2-05 只处理一份明确脱敏、字段受控的最小案例，不直接依赖或修改 `.internal/legacy-pms/`。
导入适配器必须输出逐行结果和结构化对账报告，至少核对项目编号、物料、单台数量、投产数量、
可请购判断和去重结果。

自动化测试可以使用完全虚构的脱敏样例证明技术能力；`AC-S001-043` 要求的“业务人员确认样例和
差异”仍需由使用者人工签署。退出审查必须把自动化技术通过与人工业务确认分开记录，不能用
生成样例冒充业务确认。

## 6. Phase 2 完成定义

- `SLICE-001` 正常流程可在浏览器中从登录一直走到已提交请购；
- 页面、应用服务和数据库均执行租户与权限边界；
- 45 条验收案例全部自动化，或按正式文档给出并执行人工步骤；
- 完整业务链在服务重启、升级演练、备份和空目录恢复后保持一致；
- 最小脱敏旧数据导入与对账技术流程通过，人工差异确认有明确记录；
- Ruff、mypy、pytest、Django checks、迁移漂移、锁文件和依赖审计通过；
- 代码、文档、日志和 Git 提交形成可供另一台电脑或另一 AI 继续工作的交接基线。
