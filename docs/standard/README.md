# Standard

状态：已接受

本目录是 PMS 的工程规则中心。规则同时适用于人工开发和编码 Agent。

## 规范清单

1. [代码规范](code-standard.md)：结构、依赖、类型、数据、并发和质量要求。
2. [注释规范](comment-standard.md)：教材级注释的范围、写法、示例和维护要求。
3. [命名规范](naming-standard.md)：代码、数据库、API、文件和业务术语命名。
4. [文档规范](documentation-standard.md)：文档分类、状态、链接、ADR 和维护方式。
5. [测试规范](testing-standard.md)：测试分层、命名、隔离、数据和完成标准。
6. [日志与异常规范](logging-and-error-standard.md)：错误分类、日志字段、脱敏和用户提示。
7. [安全编码规范](security-standard.md)：身份、权限、租户、输入、密钥和附件安全。
8. [Git 规范](git-standard.md)：分支、提交、评审和禁止提交内容。

## 适用优先级

冲突时按以下优先级处理：

1. 法律、合规和数据安全要求；
2. 用户在当前任务中的明确要求；
3. 已接受的 ADR 和产品需求；
4. 本目录规范；
5. 框架或语言社区默认约定。

如果确有理由偏离规范，应在代码评审或 ADR 中说明背景、范围、风险和恢复条件。

## 教学目标

本项目的“教材级”不等于代码冗长或每行都有注释。它要求：

- 代码结构展示正确的职责分离；
- 注释解释业务含义和设计原因；
- 测试展示规则、边界和失败场景；
- 文档让学习者可以从需求追踪到实现；
- 复杂方案说明为什么选它，也说明没有选择什么。
