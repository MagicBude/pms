# 安全编码规范

状态：已接受

## 1. 默认原则

- 默认拒绝，按最小权限明确授权。
- 所有客户端输入均不可信。
- 身份、权限和 tenant 上下文由服务端确认。
- 秘密与源码分离。
- 重要操作可审计。
- 安全控制必须有反向测试证明绕不过去。

## 2. 身份与会话

- 密码使用成熟的自适应密码哈希方案，不自行发明算法。
- 会话 Cookie 使用 HttpOnly、Secure 和合理 SameSite 设置。
- 登录、找回、激活和敏感操作具备速率限制。
- 退出、密码修改和管理员禁用后，应能使相关会话失效。
- 本机免登录只能是明确部署模式，不能意外带入内网或云端。

## 3. 权限

- 页面隐藏按钮不能替代服务端权限检查。
- 每个写用例明确所需权限。
- 对象级权限同时验证 tenant 和对象归属。
- 批量操作逐项或通过安全查询范围验证权限。
- 跨租户支持工具使用独立权限、显式原因和完整审计。

## 4. 多租户隔离

- 不信任请求体、查询参数或 URL 中的 tenant_id 来决定可信范围。
- 数据访问默认应用 tenant 过滤，跨租户查询使用单独接口。
- 唯一约束、缓存、后台任务、搜索索引和附件存储都隔离 tenant。
- 错误消息避免泄露其他租户记录是否存在。
- 自动化测试至少覆盖读取、修改、删除、导出和附件下载的跨租户拒绝。

## 5. 输入与输出

- 校验类型、长度、范围、枚举和业务状态。
- 数据库查询使用参数绑定。
- HTML 输出默认转义，富文本使用允许列表净化。
- 防止路径穿越、开放重定向和服务端请求伪造。
- API 分页和导出设置上限，防止资源耗尽。

## 6. 文件上传

- 不信任扩展名和客户端 MIME 类型。
- 设置单文件、单请求和租户配额。
- 使用内部随机存储键，不能把原始文件名直接作为路径。
- 上传目录不具备执行权限。
- 下载时重新检查权限，并设置安全内容类型和下载头。
- 对高风险场景预留恶意文件扫描和隔离流程。

## 7. 密钥与配置

- `.env`、生产配置、云密钥、数据库密码和许可证私钥不得提交。
- 客户端只包含许可证验证公钥，不包含签发私钥。
- 秘密通过部署环境或秘密管理服务提供。
- 日志和异常中对秘密进行遮罩。
- 建立轮换、吊销和泄露响应流程。

## 8. 许可证

- 离线许可证使用成熟数字签名算法验证完整性和来源。
- 授权签发工具位于独立私有系统，不能随产品发布。
- 机器绑定不能作为唯一安全边界，并应支持合法换机。
- 客户端时钟可能被修改，期限校验应设计回退和审计策略。
- 云端权益由服务端账户和订阅状态决定。

## 9. 依赖和供应链

- 使用锁文件和可信软件源。
- 新依赖评估维护状态、许可证、已知漏洞和权限范围。
- 构建产物可追踪到源码版本。
- 发布产物生成摘要并尽可能进行代码签名。
- 不运行 `.internal` 中来源不明的宏和 EXE 作为自动化测试步骤。

## 10. 安全评审触发条件

以下变更必须进行专门安全评审：

- 身份认证、权限或租户隔离；
- 文件上传下载；
- 支付、发票、银行和个人信息；
- 许可证和订阅；
- 外部网络调用；
- 动态代码、模板执行或命令调用；
- 管理员跨租户工具；
- 数据导入、导出和删除。
