# ADR-0008：物料图纸版本与订单图纸包

状态：已接受（2026-08-26，沿用用户授权的工程化最佳实践）

## 背景

旧“提取图纸”宏要求把名称放 A 列、件号放 B 列，再拼接为文件名，从固定磁盘目录分别复制
`.pdf` 和 `.dwg`。宏使用全局忽略错误，缺图不会形成报告；物料名称变化会破坏匹配。只读盘点旧
图纸目录还发现 405 个文件中有 382 个同步冲突副本，并混有共享配置文本和 CAD 样板，不能把
整个目录视为可信图纸库或直接打包。

## 决策

1. `MaterialDrawing` 通过租户和稳定物料 ID 关联一个不可变图纸文件，不再使用“件号 + 名称”
   作为业务键；件号、名称仅作为上传时快照和显示字段。
2. PDF 与 DWG 分别版本化。同一物料、文档格式同一时刻只有一个当前版本；新上传产生递增版本
   并把旧版本标记为已替代，不覆盖附件或数据库记录。
3. 每版保存可选设计修订号、说明、上传者、时间、原文件名、大小和 SHA-256；附件服务仍是
   二进制事实来源，图纸模型只建立受控业务关系。
4. 首版只接受 PDF 与 DWG。扩展名必须与内容签名相符：PDF 以 `%PDF-` 开头，DWG 使用已知
   `AC10xx` 文件头；浏览器声明的 Content-Type 不作为可信依据。
5. 单图纸上限沿用附件 25 MiB，生成后的 ZIP 上限为 250 MiB；原文件名不得决定存储路径，
   压缩包内名称必须去除路径分隔符、控制字符和相对路径片段。
6. 只有已签发订单可以生成图纸包。系统按订单冻结明细中的物料 ID 查找各格式当前图纸，并把
   选中的具体版本冻结为包项目；后续上传新版不会改变旧包。
7. 图纸包为 ZIP 派生附件，每次生成追加 V1、V2。包内包含 `manifest.json`，记录订单号、包版本、
   物料编码、图纸格式、图纸版本、修订号、相对路径、大小和 SHA-256。
8. 部分物料缺图时允许生成有内容的包，但清单必须列出缺失物料；全部物料都无图时拒绝生成，
   防止空 ZIP 被误认为完整交付。
9. 同一订单重复物料只打包一次当前图纸，但清单保留其对应物料身份；压缩包路径冲突使用稳定
   图纸 UUID 消歧，不能静默覆盖。
10. 上传、查看、打包和下载均执行服务端租户、权限和对象范围检查，并记录不含图纸原文的审计。

## 备选方案

- 延用件号与名称拼文件名：名称可变且旧宏已证明会静默漏图，拒绝。
- 扫描旧目录自动选择最新修改时间：同步冲突副本占绝大多数，修改时间不能代表设计版本，拒绝。
- 每次订单下载时临时收集当前图纸：会让同一包版本随时间变化，拒绝。
- 缺图时生成空包：容易被当作完整交付，拒绝。
- 将 DWG 转 PDF：首版没有可信 CAD 转换器，保留原格式而不伪造转换结果。

## 后果

- 旧图纸需要经过物料匹配、冲突去重和人工版本确认后才能迁移，不能目录级自动导入。
- 同一设计修订的 PDF 与 DWG 首版可能拥有独立内部版本号；设计修订号用于表达它们的业务对应。
- ZIP 生成增加附件空间，但保证历史订单包可复现、可校验。
