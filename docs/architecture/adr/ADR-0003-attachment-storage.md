# ADR-0003 附件存储与上传安全

状态：提议
日期：2026-08-23

## 背景

旧系统通过文件夹、文件名和超链接管理 BOM、图纸、发票、凭证和回单，部分流程甚至用文件是否存在表示业务状态。这种方式难以授权、审计、迁移和校验完整性。

PMS 需要在本机使用本地目录，在内网使用服务机目录，在云端使用对象存储，同时让业务层不依赖具体路径。上传的 Excel 和其他附件是不可信输入，不能执行宏、公式、外部链接或嵌入对象。

## 决策

### 1. 元数据与二进制分离

数据库保存附件元数据和业务关联，存储适配器保存二进制内容。

附件元数据至少包含：

- `id`、`tenant_id`；
- 原始文件名与安全显示名；
- 服务端检测的媒体类型和扩展名；
- 字节大小和 SHA-256 内容摘要；
- 随机内部 `storage_key`；
- 存储后端、版本和状态；
- 创建人、创建时间、来源和必要安全扫描结果。

原始文件名不得成为磁盘路径、唯一键或业务状态。不同租户即使内容摘要相同，也不默认共享同一个存储对象。

### 2. 存储适配器

- 本机版：应用私有数据目录中的本地文件系统。
- 内网版：服务机本地磁盘或受控存储卷，只允许 PMS 服务进程访问。
- 云端版：S3 兼容对象存储或云供应商对象存储。
- 应用层只依赖 `store`、`open`、`delete`、`exists` 和完整性检查等端口。
- 首版优先复用 Django Storage API；供应商专属配置留在基础设施层。

### 3. 存储键

存储键由服务端产生，建议结构：

```text
tenants/<tenant-id>/<yyyy>/<mm>/<attachment-id>/<version-id>
```

结构只用于隔离和运维，不成为业务契约。内部键不包含客户名、项目名、身份证号或原始文件名。

### 4. 上传流程

```text
接收分块上传
   ↓
写入隔离临时区，同时计算大小与 SHA-256
   ↓
校验上限、扩展名、容器结构和实际类型
   ↓
按文件种类执行安全解析或扫描
   ↓
创建附件元数据和业务关联
   ↓
提交后移动到正式存储并标记 AVAILABLE
   ↓
失败时补偿清理；定期对账孤儿文件和缺失文件
```

不能仅相信浏览器提供的 `Content-Type`。上传失败不得留下可下载的半成品。

### 5. 附件状态

| 状态 | 含义 |
| --- | --- |
| `PENDING` | 已接收或正在验证，不能下载或作为正式业务来源 |
| `AVAILABLE` | 校验和存储完成，可按权限使用 |
| `QUARANTINED` | 类型异常、扫描失败或需要人工复核 |
| `FAILED` | 存储或处理失败，等待补偿清理或重试 |
| `DELETED` | 已按保留策略逻辑删除，元数据与审计仍保留 |

数据库事务与文件系统不能天然形成同一原子事务，因此使用明确状态、提交后动作、幂等重试和对账任务处理故障窗口。

### 6. SLICE-001 BOM 文件规则

- 允许 `.xlsx` 和 `.xlsm`，默认单文件上限 25 MiB。
- 将文件视为 ZIP/Office 容器验证结构，不只检查后缀。
- 使用 openpyxl 只读模式读取，显式关闭工作簿。
- `keep_vba=False`；不保存、不调用、不执行 VBA。
- 不访问外部工作簿链接，不执行公式，不加载嵌入对象。
- 强制业务字段如果来自公式，只能使用文件内已有可信缓存值并显示警告；没有缓存值时阻止发布。
- 导入错误必须保留来源工作表与行号，但不能把整份真实数据写入普通日志。
- 原始来源文件保留至项目归档后再按策略清理，清理前必须有备份和审计。

### 7. 业务关联

- 业务模块拥有“某业务对象关联某附件”的关系和用途，例如 `bom_source`、`project_document`。
- `attachments` 模块拥有附件元数据和二进制生命周期。
- 关联必须带租户且验证两端属于同一租户。
- 不使用不受约束的任意 GenericForeignKey 直接绕过租户和对象权限。
- 替换附件产生新版本或新关联，不静默覆盖旧证据。

### 8. 下载与预览

- 所有下载通过受认证应用入口或短时签名地址，先验证租户和业务对象权限。
- 本地和内网不得直接把媒体目录公开映射成可猜测 URL。
- 默认使用 `Content-Disposition: attachment`，避免浏览器执行主动内容。
- 文件名做响应头安全编码；禁止路径穿越和响应头注入。
- 在线预览只针对经过验证的安全类型，并另行评审隔离策略。

### 9. 备份、恢复和删除

- 数据库备份与附件备份共享一个备份清单或时间点标识。
- 备份清单记录附件 ID、存储键、大小和摘要，恢复后自动核验。
- 删除默认先逻辑删除，再由保留策略异步清理二进制。
- 法律、合同、发票和审计类附件的保留期限按未来业务规则单独定义。
- 租户导出必须只包含该租户附件，且导出行为本身进入审计。

## 备选方案

### 把二进制存入数据库

事务一致性较直观，但会放大数据库、备份和迁移成本，不适合大量图纸和 PDF，因此不采用。

### 直接保存原始文件名

易于人工浏览，但存在冲突、路径穿越、敏感信息泄露和改名断链风险，因此只把原名作为元数据。

### 全阶段使用对象存储

接口统一，但本机版需要额外服务或云依赖，破坏离线和低门槛目标。

### 通过 Web 服务器公开媒体目录

性能简单，但难以逐对象权限和审计。以后可以使用校验后的内部转发或短时签名 URL，不直接公开原路径。

## 后果

### 正面

- 业务关联不依赖物理路径，部署形态可以切换。
- 内容摘要、状态和备份清单提升完整性与可恢复性。
- 不可信 Excel 与应用执行环境隔离。
- 下载权限和审计可以覆盖本机、内网和云端。

### 代价

- 数据库与文件存储存在故障窗口，需要状态机、补偿和对账。
- 云端对象存储需要额外适配器和运维配置。
- 原文件留存会增加存储，需要后续保留策略。
- 公式缓存和复杂 Excel 兼容需要明确错误提示，不能承诺与 Excel 完全一致。

## 复审条件

- 附件规模或上传时长需要分片、直传或后台处理。
- 引入在线预览、OCR、病毒扫描或内容搜索。
- 合规要求改变加密、保留、不可变存储或数据驻留策略。
- 需要跨区域复制或租户独立存储桶。
