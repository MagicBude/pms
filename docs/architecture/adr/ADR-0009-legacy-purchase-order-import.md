# ADR-0009：旧采购订单导入与金额差异

状态：已接受（2026-08-26，用户授权按工程化最佳实践继续推进）

## 背景

旧采购订单库包含 1,625 行、536 个订单号。只读分析确认订单号能够稳定划分单据，且每张订单
只有一个供应商；订单可能跨项目、跨请购号，少量订单同时包含采购件和加工件。另有 55 张订单
至少一行的旧“总价”与数量乘单价不一致。

旧库没有足以可靠还原税率、含税口径和报价版本的字段。新系统正式订单则要求每行能够追溯至
请购、供应商报价和确定结果，并把净额、税额和含税金额明确冻结。若直接把旧单价当作未税价或
含税价，会把未知事实伪装成已确认事实；若只导入订单头和明细，又会破坏新系统来源链约束。

## 决策

1. 迁移继续使用 `PurchaseOrder` 与 `PurchaseOrderLine`，不建立一套只能查询、不能参与后续业务
   的“历史订单影子表”。历史订单与新订单共享租户、权限、附件、图纸包和查询边界。
2. 映射分为“原始提取 → 版本化规范包 → 隔离库导入 → 自动对账 → 人工签收”五步。映射命令
   不写数据库，导入命令不直接读取旧工作簿，两者均不得回显供应商名称、价格或备注。
3. 规范包以旧订单号为订单边界，保留来源清单摘要、来源行号、项目、请购号、物料、数量、
   单价、旧保存总价、供应商、备注、日期及零件属性。原始值与规范化值必须可逐行追踪。
4. 导入前必须解析或显式报告供应商、项目、物料和请购来源。无法唯一关联、数量非正、单价无效、
   订单号为空或同一订单出现多个供应商时，整包不得写入正式库。
5. 为满足正式来源链，迁移用例创建带明确 `LEGACY_IMPORT` 来源标记的历史报价与供应商确定记录，
   再由专用仓储创建已签发订单；不得调用普通页面伪造当前询价过程，也不得绕过租户和事务边界。
6. 旧订单号原样保存为正式 `order_number`，并由租户唯一约束防重复。迁移来源另存稳定批次摘要和
   来源订单键；重复导入同一包必须复用现有事实，内容漂移则整包回滚。
7. 旧库税务口径标记为 `LEGACY_TAX_UNKNOWN`。旧单价和旧保存总价作为迁移证据单独保留，不把
   `tax_rate=0` 描述成业务确认的免税事实。
8. 规范重算金额使用 Decimal，先以精确“数量 × 旧单价”判断来源行是否不一致，再按人民币分
   四舍五入展示；厘级异常不能因展示舍入而被抹去。它只用于差异对账，不自动覆盖旧保存总价。
   差异报告逐单列出行数、旧合计、重算合计、差额和涉及来源行数。
9. 55 张已知差异订单是迁移验收基线，不是可以硬编码的结果。真实映射每次必须重新计算；数量
   变化说明源数据、解析或规则发生漂移，必须停止签收并调查。
10. 首次导入只在隔离 SQLite 数据目录演练，验证记录数、订单数、供应商边界、跨项目/跨请购、
    类型、金额差异和重复导入后，才允许用户明确选择是否导入日常本机库。

## 备选方案

- 只做历史查询影子表：会形成第二套订单权限、附件和后续履约逻辑，拒绝。
- 把旧单价统一当含税价或未税价：旧证据不足，会制造虚假税务事实，拒绝。
- 信任旧保存总价并覆盖重算结果：会掩盖 55 张已知差异订单，拒绝。
- 导入时重新生成新订单号：会切断纸质单据、附件和上下游台账的历史关联，拒绝。
- 直接运行旧宏生成中间文件：违反旧系统只读和不执行未知宏的安全边界，拒绝。

## 后果

- 迁移实现会增加来源批次、价格口径和旧金额证据字段，但避免把历史未知信息冒充当前规则。
- 旧订单可以进入新系统统一查询与后续图纸包能力；涉及税务或付款的后续功能必须识别
  `LEGACY_TAX_UNKNOWN`，不能把它当作零税率。
- 正式导入前仍需完成规范包、隔离演练、55 张差异重算和业务签收；接受本 ADR 不等于接受差异。
