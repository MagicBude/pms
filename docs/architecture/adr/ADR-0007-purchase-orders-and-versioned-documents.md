# ADR-0007：正式订单、稳定编号与版本化单据

状态：已接受（2026-08-25，用户授权按工程化最佳实践推进）

## 背景

旧采购订单库共 1,625 行、536 个订单号。只读分析确认：订单号是稳定的单据边界，每个订单只
对应一个供应商；订单可以跨项目、跨请购号，少量订单同时包含采购件和加工件。旧库另有 55 个
订单包含至少一行“保存合计不等于数量乘单价”，不能把保存合计当作新系统计算规则。

旧系统还会用供应商名称片段、日期和当日计数拼接订单号，并把输出文件是否存在作为是否打印的
依据。这些做法容易受名称修改、并发和文件丢失影响，也无法回答某次输出采用了哪一版订单事实。

## 决策

1. `PurchaseOrder` 是正式订单头；同一订单的供应商和币种必须一致，但数据模型不限制只能属于
   一个项目或请购单。
2. `PurchaseOrderLine` 引用当前供应商决策，并冻结请购、项目、物料、数量、供应商、币种、
   税率、单价及未税/税额/含税金额快照。后续档案或报价变化不得改写已生成订单。
3. 首个页面入口从一张已提交请购的当前供应商决策生成订单，按“供应商 + 币种”自动分组；
   领域模型保留未来跨请购批量合单能力。
4. 订单类型根据明细零件属性形成 `PURCHASE`、`OUTSOURCE` 或 `MIXED` 快照。旧数据确有混合
   订单，因此不能强制用单一零件属性拆单。
5. 状态为 `DRAFT → ISSUED → CANCELLED`。已签发订单及其明细不可原地修改；错误通过取消并
   新建订单更正。取消释放请购行的有效下单占用，但保留原单据和审计证据。
6. 正式编号在签发事务内分配，格式为 `PO-YYYYMMDD-NNN`、`OS-YYYYMMDD-NNN` 或
   `MX-YYYYMMDD-NNN`；序号按租户、业务日期和类型隔离，不包含供应商名称。
7. 同一请购行同一时刻最多存在一条未取消订单明细，由数据库条件唯一约束保护；重复命令必须
   幂等或明确拒绝，不得生成重复订单。
8. 订单金额只汇总冻结行快照，并使用 Decimal；不同币种绝不相加。旧保存合计只作为迁移对账
   字段，差异必须报告而不能静默吸收。
9. 正式单据是数据库事实的派生物。每次生成创建新的 `PurchaseOrderDocument` 版本并关联附件
   元数据；文件删除或重生成不会改变订单事实，旧版本仍可追溯。
10. 首版输出 `.xlsx` 采购/外协订单。PDF 在模板和签章需求确认后扩展，不用浏览器打印结果冒充
    稳定 PDF。
11. 图纸包只能收集显式关联到订单物料且有版本信息的真实图纸附件，并生成清单与校验值；BOM
    来源工作簿不视为图纸。没有图纸时明确显示待补充，不生成看似完整的空包。
12. 创建、签发、取消、生成和下载均执行服务端租户与权限检查，并写入不含自由文本和附件内容
    的审计摘要。

## 备选方案

- 每个项目或请购单固定一张订单：与旧库存在的跨项目、跨请购事实冲突，拒绝。
- 延用“供应商简称 + 日期”编号：名称可变且并发下不稳定，拒绝。
- 输出文件作为订单事实：文件可能被覆盖或删除，无法保护业务状态，拒绝。
- 自动按采购件/加工件拆单：真实订单存在混合情况，首版保留显式 `MIXED`，不擅自改变业务。
- 把 BOM 工作簿复制进图纸包：来源和用途不同，会制造错误证据，拒绝。

## 后果

- 签发后更正会产生取消单和新单，数据量增加，但换来可追溯历史。
- 页面首版按单张请购生成，未来待下单工作台可以复用同一分组和编号服务实现跨请购合单。
- 真实旧订单迁移必须同时对账订单分组、行快照和旧合计差异，不能只比较总行数。
- 图纸包交付依赖后续建立物料图纸附件及版本关系；订单 Excel 不因此被阻塞。
